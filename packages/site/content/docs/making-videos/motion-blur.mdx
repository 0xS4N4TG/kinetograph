---
title: Motion blur
description: Smear a moving layer along its path, as a camera with an open shutter does, or leave a fading trail behind it.
---

Add `motionBlur` to the layer that moves. The engine draws it at several moments inside the time the shutter is open and averages the pictures.

```tsx title="src/Whip.tsx"
import { Layer, Rect, interpolate, useCurrentFrame } from '@kinetographdev/core';

export const Whip = () => {
  const frame = useCurrentFrame();
  const x = interpolate(frame, [0, 30], [-300, 1300], { extrapolateRight: 'clamp' });
  return (
    <Layer x={x} y={300} motionBlur={{ samples: 12, shutter: 0.5 }}>
      <Rect width={240} height={120} radius={24} fill="#f6c177" />
    </Layer>
  );
};
```

`samples` is how many moments to average, from 2 to 64, default 8. `shutter` is how long the shutter is open, in frames, from 0 to 2, default 0.5. A shutter of 0.5 is a 180 degree shutter, and 1 is a 360 degree one. More samples are smoother and slower, because the layer is drawn once for each.

## What blurs

The layer and everything under it blurs: position, rotation, scale, 3D turns, opacity, effect settings and shape changes, and what the children do relative to each other. Put `motionBlur` on the group that moves, so the whole group smears.

`motionBlur({ samples })` also works inside the `effects` array, next to other effects: `effects={[blur(2), motionBlur({ samples: 8 })]}`.

## Remotion's components

`CameraMotionBlur` from `@remotion/motion-blur` is the same thing: a `Layer` with `samples` (default 10) and `shutterAngle` in degrees (default 180). `Trail` stacks fainter copies a few frames behind instead:

```tsx title="src/Comet.tsx"
import { Trail } from '@kinetographdev/core/motion-blur';
import { Ball } from './Ball';

export const Comet = () => (
  <Trail layers={6} lagInFrames={1} trailOpacity={0.6}>
    <Ball />
  </Trail>
);
```

Give the children of a `Trail` no `id`, because they are drawn once for each copy.

## Rules

- **Only the layer moves.** Its parents and the `Camera` are taken at the frame itself, so a camera move is not blurred. Move the layer that has the `motionBlur`.
- **Nesting.** A `motionBlur` inside a blurred layer is ignored.
- **3D.** A `preserve3d` layer and its children cannot have `motionBlur`. Wrap the stack in an ordinary `Layer` and blur that.
- **Noise.** `grain` and a random `dither` use the output frame, so the samples share one pattern. A custom `shader` sees each sub-frame's time.
- **Still layers.** A layer that does not move can differ from the same layer without `motionBlur` by about 1 part in 1000. Use `shutter: 0`, or leave it out.
- **Libraries.** For GSAP in a sample, only `onUpdate` runs, not `onStart`, `onComplete`, `onRepeat` or `call()`.

## What works

- Drawn natively: `motionBlur` on any layer, `CameraMotionBlur` and `Trail`.
- Approximated: a still layer carries a small rounding error, as above.
- Not supported: `HtmlInCanvasMotionBlur` from `@remotion/motion-blur`, and blur of a camera move.
- Check the result with `strip`. See [What works](/docs/compat/#remotion-packages) and the [scene format](/docs/reference/scene-format/).
