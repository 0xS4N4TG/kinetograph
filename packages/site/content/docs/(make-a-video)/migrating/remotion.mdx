Most Remotion projects run on Kinetograph as they are.

Your `remotion` and `@remotion/*` imports are mapped onto Kinetograph's own versions of those packages. You don't edit them.

Three things need work:

- The tooling around the video.
- A few packages that have no equivalent.
- Anything the engine can't draw yet.

To keep editing in Remotion and only render with Kinetograph, see [Keep your editor, render with Kinetograph](/docs/keep-your-editor/). An agent can do this for you. See [Use with agents](/docs/agents/) for the `kinetograph-migrate` skill.

## How much of Remotion is covered

Kinetograph exports 310 of the 318 names in `remotion` and the 24 `@remotion/*` packages it maps, counted in Remotion 4.0.540. A name that exists can still have gaps: [What works](/docs/compat/) lists them. Run `doctor` to see what your project uses.

## Package by package

### Packages that work

`remotion`, `@remotion/transitions`, `@remotion/motion-blur`, `@remotion/noise`, `@remotion/paths`, `@remotion/shapes`, `@remotion/layout-utils`, `@remotion/animation-utils`, `@remotion/captions`, `@remotion/google-fonts`, `@remotion/fonts`, `@remotion/lottie`, `@remotion/gif`, `@remotion/media-utils`, `@remotion/media`, `@remotion/light-leaks`, `@remotion/starburst`, `@remotion/sfx`, `@remotion/zod-types`, `@remotion/timeline-utils`, `@remotion/canvas` and `@remotion/rive` work as usual. The few missing names, such as `HtmlInCanvasMotionBlur` and `getAvailableFonts`, are listed on [What works](/docs/compat/#remotion-packages). `@remotion/canvas` is Remotion Studio's editor canvas: it bundles, but every call throws `UnsupportedApiError`.

### Packages that work in part

| Package | Status | Exports present | Notes |
|---|---|---|---|
| `@remotion/media-parser` | Partly | 13 of 13 | Local files only. There is no box tree and there are no sample callbacks. See [What works](/docs/compat/#remotion-packages). |
| `@remotion/webcodecs` | Partly | 24 of 24 | Encode and decode throw `UnsupportedApiError`. `convertMedia` writes sound to WAV. |
| `@remotion/skia` | Partly | 1 of 1 | Needs the `@kinetographdev/skia` add-on. Some Skia features are not drawn. It also covers `@shopify/react-native-skia`. |

### Packages that Kinetograph replaces

| Package | Status | Exports present | Use instead |
|---|---|---|---|
| `@remotion/three` | Not planned | not counted | The own 3D layer, `Scene3D`. The steps are in the [skill](#the-agent-skill). |
| `@remotion/player` | Not planned | 0 of 3 | The studio, with `kinetograph studio`. There is no embeddable player. |
| `@remotion/renderer` | Not planned | 0 of 22 | `kinetograph render`, `still` and `compositions`. |
| `@remotion/bundler` | Not planned | 0 of 4 | Nothing to do. `render` bundles for you. |
| `@remotion/cli` | Not planned | 0 of 2 | The `kinetograph` CLI. |
| `@remotion/lambda` | Not planned | 0 of 25 | There is no cloud renderer. Run `kinetograph render` on a machine with a GPU. |
| `@remotion/cloudrun` | Not planned | 0 of 14 | Same as Lambda. |
| `@remotion/studio` | Not planned | 0 of 18 | `kinetograph studio`. |
| `@remotion/tailwind`, `@remotion/tailwind-v4` | Not planned | 0 of 1 each | They only configure webpack. Tailwind itself works. |
| `IFrame` (from `remotion`) | Not planned | exported | It needs a browser. It is reported as unsupported and left out. |

Any other `@remotion/*` import stops the build with `"..." is not supported by Kinetograph yet`.

## Migrate by hand

Follow these steps in order.

1. **Find the entry.** It is the file that calls `registerRoot`, often `src/index.ts`. Check that it loads with `compositions`. If an import is not supported, the command stops and names it. Fix that first.
2. **Run doctor.** It goes through every frame without the GPU. It lists each element and property the engine can't draw, and the frames they happen on.
3. **Fix each finding.** The common cases are below.
4. **Lint and look.** `lint` checks the project. `strip` draws twelve frames into one picture. Open it.
5. **Render with `--strict`.** It stops on the first frame with something unsupported, so nothing is silently missing.
6. **Write down what changed.** The video can differ from the Remotion one.

The commands differ only in the entry. A Remotion project points at its entry file and picks a composition with `--comp`. A [HyperFrames](/docs/migrating/hyperframes/) page points at its `index.html`.

### Fixing findings

- **Tooling imports** (`player`, `renderer`, `bundler`, `lambda`): remove them and use the CLI.
  - `remotion render` becomes `kinetograph render <entry> --comp <id>`.
  - `remotion studio` becomes `kinetograph studio <entry>`.
- **`@remotion/three`**: rebuild the scene with `Scene3D`, `Camera3D`, lights, `Mesh` and `Model`. Rotations are in degrees. See [AUTHORING.md](https://github.com/0xS4N4TG/kinetograph/blob/main/packages/cli/skills/kinetograph/references/AUTHORING.md), section 6.6.
- **`IFrame`**: rebuild the page as components, or use a screenshot.
- **A CSS property or element in the report**: change it to one the engine draws, or remove it.

Nothing in this path starts a browser. If something can't be ported, leave it out or approximate it. See [What works](/docs/compat/) for how warnings work.
