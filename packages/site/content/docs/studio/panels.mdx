A panel is a box in [Studio](/docs/studio/). There are two kinds. An **agent panel** is a question your coding agent puts to you: a brief, a script, a storyboard, a choice of looks, a review, or a form of its own. A **plugin panel** is an editor a plugin draws for one field of a composition's props. (Studio's window also has four fixed panels, the top bar, the agent chat, the preview and the inspector. They are described on the [Studio](/docs/studio/#the-window) page.)

## Agent panels

An agent that works inside Studio opens a panel with the `studio_open_panel` tool, and then ends its turn. It doesn't wait or poll. When you submit, your answer arrives as the agent's next message, and it is saved under `plan/` beside the project's entry file, so a restart keeps it.

```txt title="Suggested prompt"
/kinetograph-studio Open a brief panel for a 30 second launch video and wait for my answers before you plan anything.
```

### The six kinds

| Panel | What you decide | Saved in |
|---|---|---|
| `brief` | Purpose, audience, platform, size, length, the one takeaway, and references | `plan/brief.json` |
| `script` | The lines of the script and their seconds, or a music track with its beats | `plan/script.json` |
| `storyboard` | A card for each shot: what it shows, how it moves, its line, seconds and transition | `plan/storyboard.json` |
| `styleframes` | Which of several looks, shown as frames of a composition, to use, or how to mix them | `plan/styleframes.json` |
| `review` | Notes on frames of a composition, with boxes drawn on the picture, then approve or ask for changes | `plan/review.json` |
| `custom` | Whatever the agent lays out from blocks, as below | `plan/custom-<name>.json` |

A stage strip in Studio shows where the video stands: Brief, Script, Board, Style, Animatic, Build, Deliver. A stage is open while its panel waits and approved once you approve it. You can put a panel away and bring it back from the strip.

### What the agent does

- `studio_open_panel({ panel, data, message?, placement? })` opens the panel and returns `{ id, status: "open" }` at once. `data` is what the panel starts from. `message` is one line shown at the top.
- You answer in the window. The agent's next message starts `[panel <kind> <id> submitted]`, followed by the answer in short form, or `[panel <kind> <id> dismissed]` if you closed it. A custom panel is named in it, as `custom:<name>`.
- `studio_panel_result({ id })` returns `{ status, answer? }`. It is for an agent in a terminal that you told you had answered. Inside Studio the answer comes as a message.
- Opening a second panel of the same kind replaces the first. Custom panels are told apart by name, so several can be open together.
- While the agent is still working, your answer waits in the **Up next** tray and goes to it when its turn ends.

`placement` says where a panel shows: `sheet` over the preview and timeline (the default), `beside-preview` for a column that keeps the preview in view (the default for a review), `left` as a tab beside the agent chat, or `right` as a tab beside the inspector.

## A custom panel

A custom panel is data, not code. The agent sends a name, a title and a list of blocks, and nothing it sends runs. The blocks that show something are `heading`, `text` (paragraphs and `**bold**`), `still` (a frame of a composition) and `clip` (a range of frames that plays in place). The blocks that take an answer are:

| Block | The answer for its `id` |
|---|---|
| `choice` | The chosen option's id, or a list of ids with `multiple`. Options can show a still. |
| `slider` | A number from `min` to `max` |
| `input` | Text, with `multiline` for a long answer |
| `list` | A list of texts, which you can add to, remove from and reorder when `editable` |
| `table` | Rows of texts, one cell for each column |
| `notes` | A list of notes, each with a box if you drew one on the picture |
| `compare` | `a`, `b` or nothing, for two frames side by side |

Every block has an `id` (a letter first, unique in the panel) and can have `label`, `help` and `required`, which keeps the submit button waiting. The limits are 40 blocks and 24 options in a choice. The server checks both the panel and your answer against them.

Here is a complete one. The agent asks you to pick between two end cards:

```ts
studio_open_panel({
  panel: 'custom',
  placement: 'right',
  message: 'Two end cards',
  data: {
    name: 'end-card',
    title: 'Pick the end card',
    blocks: [
      { id: 'pick', type: 'choice', required: true, options: [
        { id: 'a', label: 'Plain', still: { comp: 'End', frame: 40 } },
        { id: 'b', label: 'Loud', still: { comp: 'End', frame: 90 } },
      ] },
      { id: 'speed', type: 'slider', label: 'Logo speed', min: 0.5, max: 2, value: 1, unit: 'x' },
      { id: 'why', type: 'input', label: 'Anything else?', multiline: true },
    ],
  },
});
```

You choose, move the slider and submit. The agent's next message reads `[panel custom:end-card p_1 submitted] pick=b, speed=1.2 x, why="..."; see plan/custom-end-card.json`, and the file holds the question and the answer:

```json title="plan/custom-end-card.json"
{
  "draft": { "name": "end-card", "title": "Pick the end card", "blocks": ["..."] },
  "answer": { "values": { "pick": "b", "speed": 1.2, "why": "Make the logo hit on the beat." } }
}
```

The agent reads `answer.values` and uses `draft` to see which block each value belongs to. To ask for one yourself, say so: "open a panel where I rate each shot from 1 to 5".

## Plugin panels

A [plugin](/docs/plugins/) can draw its own editor for a field. Studio shows the field as a card in the **Props** tab, with the plugin's panel inside it, in place of the generated form. The panel can also draw guides and handles on the preview.

A field points at its panel with zod meta, and the plugin's `package.json` names the panel module:

```json title="package.json"
{ "name": "my-plugin", "kinetograph": { "panel": "./studio/panel.ts" } }
```

```ts title="src/schema.ts"
import { z } from 'zod';

export const seedSchema = z.number().min(0).max(999).meta({ kinetographPanel: 'my-plugin' });
```

The module exports `mount`, which gets a plain element and a context with the field's `value` and an `onChange` that sets it and redraws the preview:

```ts title="studio/panel.ts"
export function mount(el: HTMLElement, ctx: { value: unknown; onChange(value: unknown): void }) {
  const slider = document.createElement('input');
  slider.type = 'range';
  slider.min = '0';
  slider.max = '999';
  slider.value = String(ctx.value ?? 0);
  slider.addEventListener('input', () => ctx.onChange(Number(slider.value)));
  el.append(slider);
  return {
    update(next: { value: unknown }) {
      slider.value = String(next.value ?? 0);
    },
    unmount() {
      slider.remove();
    },
  };
}
```

A render never runs a panel. If one throws, Studio shows an error box and the rest of the form keeps working. The full context (`schema`, `path`, `state`, `preview.overlay`) and the rest of the plugin format are on [Writing a plugin](/docs/plugins/writing-a-plugin/#the-panel). The card's menu also copies the path of the plugin's `SKILL.md` and asks the agent about the plugin. See [Props and presets](/docs/studio/#props-and-presets).

## Plan well with panels

For a new video, ask the agent to go in order: brief, script, storyboard, styleframes, then a review of a rough cut before it animates. Skip a stage that doesn't fit. A caption fix needs no brief. [Storyboards](/docs/tips/storyboards/) shows how to write the plan that goes into these panels.

## Over MCP

`studio_open_panel` and `studio_panel_result` are two of the four tools Studio adds to its agent, beside `studio_get_props` and `studio_set_props`. An agent in a terminal can reach them with `KINETOGRAPH_STUDIO_TOKEN=<token> npx kinetograph mcp --studio http://127.0.0.1:3000`. See [Studio's agent](/docs/plugins/#studios-agent).
