---
title: Editing an existing video
description: How to change a Kinetograph, Remotion or HyperFrames project with an agent, by marking up the preview, changing one thing and proving nothing else moved.
---

Mark the problem in Studio, or name the frame and the layer, and ask for one change. Lock the frames you like first, so a snapshot shows you anything else that moved.

## Mark it up in Studio

Press `M` in Studio. Pin a spot, draw a box, draw freehand, or drag across the timeline ruler to mark a span of time, and write a note by each mark. Send the notes and the agent gets them in time order, with the frame, the coordinates, the layers under each mark, and a picture of each marked frame. See [Studio](/docs/studio/#mark-up-the-preview).

```txt title="Suggested prompt"
/kinetograph-studio Fix my markup notes in order. When you finish, list which you did and which you skipped, with the reason.
```

Without Studio, name the place: "the subtitle at 0:07, the second line, is cut off on the right". The frame and the words are enough for the agent to find the layer with `inspect`.

## One change at a time

- **Say what changes and what stays.** "Move the logo to the top right. Leave everything else as it is."
- **Name the frame.** "At frame 120 the title sits on top of the photo."
- **Use absolute targets.** "The headline at 140 px", "the pause at 0:04 is 20 frames", not "bigger" or "shorter".
- **Don't ask for a redesign in the same message as a fix.**

## Prove nothing else moved

Before the edit, approve the frames that are right. After it, compare:

```txt title="Suggested prompt"
/kinetograph-render Save frames 0, 60, 120 and 179 as approved snapshots. Then move the logo to the top right, and run snapshot. Tell me which frames changed and why each should have.
```

`snapshot --update` writes the approved PNGs beside the entry, and `snapshot` on its own fails on any frame that differs by more than 2 levels in a channel. A frame that changed when you didn't mean it to is a regression. See the [CLI reference](/docs/reference/cli/#snapshot).

## Retime, cut and extend

Give the new length in seconds and say what absorbs it: "Make the whole video 18 seconds. Shorten scene 2, and leave the others." A transition shortens the video by its length, so mention the total. For audio, say whether it moves with the picture or stays put.

## Edit a Remotion or HyperFrames project

Kinetograph runs both as they are, and an agent can edit them in place. Say which kind it is, and keep the changes inside the project's own style: "edit the HTML page and keep the GSAP timeline". Run `doctor` after the edit to see whether the change added anything the engine can't draw. Moving a Remotion project to Kinetograph's own elements is a separate job. See [Migrating](/docs/migrating/remotion/).

## Put titles over a video file

An exported video file is not a project. To add to it, ask for a new composition that plays the file with `Video` and puts layers over it: "Use public/video/talk.mp4 as the background, mute it, and add a title at 0:02". Edits are then layers, not changes to the file.

## Common mistakes

- "Fix the timing" with no frame or scene.
- Two edits in one message, so a regression has two suspects.
- Editing without approved frames to compare against.
- Forgetting `doctor` after pulling in new HTML or CSS.
