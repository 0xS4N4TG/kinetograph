title: Plugins

A [plugin](/docs/terminology/plugin/) is an npm package that adds components or effects to Kinetograph projects. It also tells Studio and coding agents how to use them. Studio shows its props as form fields, and an agent reads its skill. A plugin can also draw its own panel in Studio for a field a generic form cannot edit well.

The first part of this page is for people who write plugins. The second is for people who use Studio and want to save props.

## For plugin authors

### The manifest

Add a `kinetograph` field to the package's `package.json`. A package with this field is a plugin.

```json
{
  "name": "@kinetographdev/hexed",
  "kinetograph": {
    "skill": "./SKILL.md",
    "panel": "./studio/panel.ts",
    "tools": "./tools.ts",
    "title": "Hexed",
    "description": "Dice-rolled hex genomes drawn as ornaments.",
    "icon": "./icon.svg",
    "components": ["Genome", "GenomeRing"]
  }
}
```

All keys are optional. Paths are relative to the package root.

- `skill`, `panel` and `tools` point at the plugin's skill file, panel module and MCP tools module.
- `title` and `description` name the plugin on its card in Studio. Without a `title`, Studio shows the package name without its scope.
- `icon` is an SVG file. Studio draws it in the text colour, so use `currentColor`.
- `components` lists the React components that draw layers. Studio uses it to link a card to its layers.

Kinetograph finds a project's plugins in the `dependencies` and `devDependencies` of the nearest `package.json` above the project's entry.

### The props schema

Export zod (v4) schemas for your components' props. Put `.describe()` on every field a person sets. Studio shows it under the field's label.

```tsx
import { z } from 'zod';

export const genomeSchema = z.object({
  seed: z.number().min(0).max(999).describe('Picks the pattern. The same seed always draws the same one.'),
  palette: z.enum(['ember', 'ice', 'moss']).describe('The colours the pattern is drawn in.'),
});
```

A project uses the schema in its composition:

```tsx
<Composition id="Hero" schema={z.object({ look: genomeSchema, title: z.string() })} defaultProps={...} ... />
```

Studio builds its form from the schema. If there is no schema, or it is not a zod 4 schema, Studio infers the fields from `defaultProps`.

| Schema | Field |
|---|---|
| `z.enum([...])` | A select |
| `z.number().min(a).max(b)` | A slider with a number box |
| `z.boolean()` | A switch |
| `zColor()` from `@kinetographdev/core/zod-types` | A colour input and a text box |
| `zTextarea()` | A text area |
| `z.object({...})` | A labelled group of fields |

Anything else falls back to a field inferred from the default value, or a JSON box.

### The panel

For a field that needs more than a form, point it at your panel with zod meta. The value is the plugin's package name.

```ts
genomeSchema.meta({ kinetographPanel: '@kinetographdev/hexed' })
```

Studio then draws the plugin's panel in place of the generated form. The panel is an ES module named by `kinetograph.panel`. It exports `mount`:

```ts
export interface PanelContext {
  value: unknown; // the field's current value
  schema: Record<string, unknown>; // the field's JSON Schema
  path: string[]; // where the field is in the props
  onChange(value: unknown): void; // sets the field and re-renders the preview
  state?: unknown; // what the panel last passed to setState
  setState(state: unknown): void; // keeps panel-only state in the browser
  preview?: { overlay: HTMLElement; width: number; height: number; frame: number };
}

export function mount(el: HTMLElement, ctx: PanelContext): {
  update(ctx: PanelContext): void; // the value changed from outside
  unmount(): void;
};
```

Some rules:

- Studio bundles the module for the browser. Do not rely on Studio's React. Bring your own.
- The panel gets a plain element with no shadow root. Scope your CSS under a class of your own.
- To match the theme, read Studio's CSS variables, such as `--background`, `--foreground` and `--primary`.
- `preview.overlay` is an element laid over the preview, in composition pixels. Draw guides or handles in it.
- A render never runs the panel. If it throws, Studio shows an error box and the rest of the form keeps working.

### Tools

A plugin can offer tools that a coding agent calls over MCP. Point `tools` at a module that exports a `tools` array:

```ts
import { z } from 'zod';

export const tools = [
  {
    name: 'roll',
    description: 'Rerolls the unlocked slots of a genome, or all slots.',
    input: z.object({ seed: z.number().optional().describe('Seed for the dice') }),
    run: ({ seed }) => ({ /* data that serialises to JSON */ }),
  },
];
```

`name` is snake_case and unique in the plugin. `input` is a zod 4 object schema. `run` takes the parsed input and returns JSON data. It never writes files, renders or fetches.

`kinetograph mcp` registers each tool as `<short>_<name>`, where `<short>` is the package name without its scope and with `-` turned into `_`. So `@kinetographdev/hexed` with a `roll` tool gives `hexed_roll`.

### SKILL.md

Ship a `SKILL.md` in the package. It should say:

- What the plugin does, in a sentence or two.
- Its components, their props and its presets.
- Two or three short examples.
- What to check with `npx kinetograph still`.

An agent finds the file with `npx kinetograph plugins`, which prints the path of each installed plugin's `SKILL.md`. Add `--json` for a machine-readable list. Over MCP, use the `plugins` tool.

## For people using Studio

### Presets

A preset is a named set of props for one composition. In the Props tab of [Studio](/docs/guides/studio/), the **Presets** menu loads a saved preset, and **Save preset** saves the props you are previewing under a name.

A preset is a JSON file at `presets/<composition id>/<name>.json`, next to the project's entry file. You can commit it or edit it by hand. A name uses lower-case letters, digits, `-` and `_`, starts with a letter or digit, and has at most 64 characters.

### Render with a preset

`--props` takes the path of a JSON file as well as a JSON object:

```sh
npx kinetograph still src/index.tsx --comp Hero --props presets/Hero/warm.json
```

A value that starts with `{` is read as JSON. Any other value is a file path.

### Studio's routes

Studio serves a small HTTP API for tools that talk to it:

- `GET /api/plugins` lists the plugins. Each plugin's icon and bundled panel are under `/api/plugins/<name>/`.
- `GET /api/presets?comp=<id>` lists a composition's presets. `PUT /api/presets/<id>/<name>` writes one from a JSON body.
- `GET /api/live-props` and `PUT /api/live-props` read and set the `{ comp, props }` that every window previews.

The live-props routes need the Studio token in the `x-studio-token` header. It is the `token` in the address Studio opens.

### Studio's agent

The coding agent in Studio's chat panel gets a Kinetograph MCP server. It has every `kinetograph` tool, your plugins' tools, and four tools for the open window:

- `studio_get_props` returns `{ comp, props }`, what the preview shows now.
- `studio_set_props` takes `{ comp?, props, merge? }`. It merges the props over the current ones, or replaces them with `merge: false`. The preview and the Props tab update.
- `studio_open_panel` takes `{ panel, data, message?, placement? }` and opens a brief, script, storyboard, styleframes, review or custom panel to ask the person for a decision. The agent ends its turn, and the answer arrives later as a message starting `[panel <kind> <id> submitted]`. It is also saved in `plan/<kind>.json`.
- `studio_panel_result` takes `{ id }` and returns `{ status, answer? }`. It is for an agent in a terminal that the person told.

An agent in Studio should try values with `studio_set_props`, then write the values it picks into the code or a preset.

To run the same server outside Studio:

```sh
KINETOGRAPH_STUDIO_TOKEN=<token> npx kinetograph mcp --studio http://127.0.0.1:3000
```
