description: Every Remotion package a video can import, what works in Kinetograph, what doesn't, and the steps to move a project.

Most Remotion projects run on Kinetograph as they are. Your `remotion` and `@remotion/*` imports are mapped onto Kinetograph's own versions of those packages. You don't edit them. What needs work is the tooling around the video, a few packages with no equivalent, and anything the engine can't draw yet.

An agent can do this for you. See [Use with agents](/docs/guides/agents/) for the `kinetograph-migrate` skill.

## How much of Remotion is covered

For `remotion` itself, Kinetograph exports **57 of 59** names. The two missing ones, `Internals` and `FolderContext`, are Remotion's own internals.

Across `remotion` and the 24 `@remotion/*` packages that Kinetograph maps, it exports **309 of 316** names. Seven are missing: the two above, plus `HtmlInCanvasMotionBlur`, `PathInternals`, `CaptionsInternals`, `AudioForPreview` and `getAvailableFonts`. The other 90 names come from nine packages that are left out on purpose (the tooling, below).

What this number means:

- It counts runtime names that exist (functions, components, constants), measured against Remotion 4.0.536. Types are not counted.
- It does not mean every name does everything. A name can exist and still have gaps. The status column below says which, and [Known issues](/docs/known-issues/) lists the gaps.
- It does not count names Kinetograph adds. The `remotion` entry alone has 105 more, such as `Layer` and `Scene3D`.
- Do not read it as "99% of your project works". A project is a mix of names, and `doctor` tells you what yours uses.

## Migrate by hand

1. **Find the entry.** It is the file that calls `registerRoot`, often `src/index.ts`. Run `npx kinetograph compositions src/index.ts` to check that it loads. If an import is not supported, the command stops and names it. Fix that first.
2. **Run doctor.** `npx kinetograph doctor src/index.ts` goes through every frame without the GPU. It lists each element and property the engine can't draw, and the frames it happens on.
3. **Fix each finding.**
   - Tooling imports (`player`, `renderer`, `bundler`, `lambda`): remove them and use the CLI. `remotion render` becomes `kinetograph render <entry> --comp <id> -o out.mp4`, and `remotion studio` becomes `kinetograph studio <entry>`.
   - `@remotion/three`: rebuild the scene with `Scene3D`, `Camera3D`, lights, `Mesh` and `Model`. Rotations are in degrees. See [Authoring](https://github.com/0xS4N4TG/kinetograph/blob/main/docs/AUTHORING.md), section 6.6.
   - `IFrame`: rebuild the page as components, or use a screenshot.
   - A CSS property or element in the report: change it to one the engine draws, or remove it.
4. **Lint and look.** `kinetograph lint src/index.ts`, then `kinetograph strip src/index.ts -n 12 -o out/strip.png` and open the picture.
5. **Render with `--strict`.** `kinetograph render src/index.ts --comp <id> -o out/video.mp4 --strict`. It stops on the first frame with something unsupported, so nothing is silently missing.
6. **Write down what changed.** For anything you left out or approximated, note it. A video can differ from the Remotion one.

Nothing in this path starts a browser. If something can't be ported, leave it out or approximate it. See [Remotion compatibility](/docs/compat/) for how warnings work.

## The agent skill

The `kinetograph-migrate` skill follows these steps for an agent. It has reference files for 3D, tooling and unsupported content, and loads them only when a finding needs one. See [Use with agents](/docs/guides/agents/#install-the-skills).
