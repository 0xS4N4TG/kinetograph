Most Remotion projects run on Kinetograph as they are.

Your `remotion` and `@remotion/*` imports are mapped onto Kinetograph's own versions of those packages. You don't edit them.

Three things need work:

- The tooling around the video.
- A few packages that have no equivalent.
- Anything the engine can't draw yet.

An agent can do this for you. See [Use with agents](/docs/guides/agents/) for the `kinetograph-migrate` skill.

## How much of Remotion is covered

Kinetograph exports 309 of the 316 names in `remotion` and the 24 `@remotion/*` packages it maps. Another 90 names belong to nine tooling packages that are left out on purpose.

Read the number with care:

- It counts runtime names (functions, components, constants) in Remotion 4.0.536. Types are not counted.
- A name that exists can still have gaps. [Known issues](/docs/known-issues/) lists them.
- It is not "99% of your project works". Run `doctor` to see what yours uses.
- Names that Kinetograph adds are not counted. `remotion` alone has 105, such as `Layer` and `Scene3D`.

Any other `@remotion/*` import stops the build with `"..." is not supported by Kinetograph yet`.

Counts come from loading the built modules in Node and from each Remotion package's published export list.

## Migrate by hand

Follow these steps in order.

1. **Find the entry.** It is the file that calls `registerRoot`, often `src/index.ts`. Check that it loads with `compositions`. If an import is not supported, the command stops and names it. Fix that first.
2. **Run doctor.** It goes through every frame without the GPU. It lists each element and property the engine can't draw, and the frames they happen on.
3. **Fix each finding.** The common cases are below.
4. **Lint and look.** `lint` checks the project. `strip` draws twelve frames into one picture. Open it.
5. **Render with `--strict`.** It stops on the first frame with something unsupported, so nothing is silently missing.
6. **Write down what changed.** Note anything you left out or approximated. The video can differ from the Remotion one.

The commands for steps 1, 2, 4 and 5 are below. They differ only in the entry. A Remotion project points at its entry file and picks a composition with `--comp`. A [HyperFrames](/docs/guides/migrate-hyperframes/) page points at its `index.html` or the directory that holds it.

<Tabs items={['Remotion', 'HyperFrames']}>
  <Tab value="Remotion">

```sh
npx kinetograph compositions src/index.ts
npx kinetograph doctor src/index.ts
npx kinetograph lint src/index.ts
npx kinetograph strip src/index.ts -n 12 -o out/strip.png
npx kinetograph render src/index.ts --comp <id> -o out/video.mp4 --strict
```

  </Tab>
  <Tab value="HyperFrames">

```sh
npx kinetograph compositions index.html
npx kinetograph doctor index.html
npx kinetograph strip index.html -n 12 -o out/strip.png
npx kinetograph render index.html -o out/video.mp4 --strict
```

  </Tab>
</Tabs>

### Fixing findings

- **Tooling imports** (`player`, `renderer`, `bundler`, `lambda`): remove them and use the CLI.
  - `remotion render` becomes `kinetograph render <entry> --comp <id> -o out.mp4`.
  - `remotion studio` becomes `kinetograph studio <entry>`.
- **`@remotion/three`**: rebuild the scene with `Scene3D`, `Camera3D`, lights, `Mesh` and `Model`. Rotations are in degrees. See [Authoring](https://github.com/0xS4N4TG/kinetograph/blob/main/packages/cli/skills/kinetograph/references/AUTHORING.md), section 6.6.
- **`IFrame`**: rebuild the page as components, or use a screenshot.
- **A CSS property or element in the report**: change it to one the engine draws, or remove it.

Nothing in this path starts a browser. If something can't be ported, leave it out or approximate it. See [Remotion compatibility](/docs/compat/) for how warnings work.

The `kinetograph-migrate` skill follows these steps for an agent.

It has reference files for 3D, tooling and unsupported content. It loads them only when a finding needs one.
