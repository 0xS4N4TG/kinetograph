`@remotion/effects` is Remotion's package of shader effects (`blur()`, `vignette()`, `glow()`) for canvas components. Kinetograph runs the copy in your project's `node_modules`. It ships none of Remotion's effect code, so install the package yourself, at the same version as `remotion`.

```tsx
import { CanvasImage } from 'remotion';
import { blur } from '@remotion/effects/blur';
import { vignette } from '@remotion/effects/vignette';

<CanvasImage src={staticFile('photo.png')} effects={[blur({ radius: 12 }), vignette()]} />;
```

- `effects` works on `<Solid>`, `<CanvasImage>`, `<AnimatedImage>`, `<HtmlInCanvas>` and Rive. Not yet on `<Img>`, `<Video>`, `<Gif>` or the `@remotion/shapes` components.
- Most effects have a WebGPU and a WebGL 2 implementation, a few also a 2D one. Kinetograph tries WebGPU, then WebGL 2, then 2D, and uses the first that draws the frame. It warns once when it falls back. Set `KINETOGRAPH_PREFERRED_EFFECT_BACKEND` to `webgpu`, `webgl2` or `2d` to try one first.
- Kinetograph blends layers in linear light and Chrome in sRGB. An effect that leaves translucent pixels (`vignette()` over a transparent image, a shadow) therefore looks lighter over a coloured background than in Remotion. With the scene's `blendSpace` set to `srgb` the two agree.
- State from `setup` doesn't carry to the next frame. See [What works](/docs/compat/).

## Status

Each effect is rendered by Remotion in Chrome and by Kinetograph, at frame 0, 960 × 540, and compared by PSNR. Supported means 50 dB or more on the backend Kinetograph picks. The table is generated from that run, with one set of parameters per effect.
