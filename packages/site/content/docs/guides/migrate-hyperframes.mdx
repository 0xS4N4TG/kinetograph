title: Migrate from HyperFrames
description: Render a HyperFrames project with Kinetograph as it is, the commands that replace the HyperFrames CLI, and what to check.
---

A HyperFrames project needs no rewrite. Kinetograph reads its `index.html`, the compositions it mounts and the scripts it loads, and renders them without a browser. You keep the HTML, the `data-*` attributes and the GSAP timelines. Only the command changes.

| HyperFrames | Kinetograph |
|---|---|
| `npx hyperframes preview` | `npx kinetograph studio my-video` |
| `npx hyperframes render` | `npx kinetograph render my-video -o out.mp4` |

`my-video` is the project directory or its `index.html`. Install Kinetograph first: see [Installation](/docs/getting-started/installation/). The [CLI reference](/docs/reference/cli/) lists every command.

## Move a project

1. **Check the root element.** The outermost `data-composition-id` element gives the size (`data-width`, `data-height`) and the length (`data-duration`). The rate is 30 fps. A page without these renders at 1920 x 1080 for one second, with a warning.
2. **Run doctor.** `npx kinetograph doctor my-video` lists what the engine can't draw, and the frames it happens on.
3. **Look at it.** `npx kinetograph strip my-video -n 12 -o out/strip.png` draws twelve frames into one picture.
4. **Render with `--strict`.** `npx kinetograph render my-video -o out.mp4 --strict` stops on the first frame with something unsupported.

### Downloads and the lock file

Before the first frame, Kinetograph downloads what the page loads from the web. That means CDN scripts, ES modules, data files, remote pictures, media and Google Fonts.

- The files go in a local cache. Each one is pinned in `kinetograph.lock.json` beside the entry. Commit that file.
- `render`, `still`, `doctor` and `studio` do this step themselves. Run `npx kinetograph fetch-deps my-video` on its own in CI or to warm the cache.
- A host other than the default CDNs needs `--allow-host`.
- Add `--offline` to a render to make it read only the cache.

## What carries over

These work as they do in HyperFrames. The details are in [HyperFrames projects](/docs/compat/#hyperframes-projects).

- Compositions mounted with `data-composition-src`, `data-variable-values` and `getVariables()`.
- Clips with `data-start`, `data-duration` and `data-hidden`.
- Timelines on `window.__timelines`.
- `<video>` and `<audio>`, with `data-media-start`, `data-playback-rate`, `data-volume` and fades.
- Speed ramps and volume lanes (`data-automation`), audio effect chains (`data-fx-chain`) and colour grading (`data-color-grading`).
- The 18 font families HyperFrames embeds, and its mapping of system font names onto them.
- WebGPU shader blocks (`shaders.iife.js`), import maps and ES modules.

## What to check

- **Three.js** is not drawn. A page that loads it is reported on every frame.
- **A tween on GSAP's root clock** renders, with a warning. This is a `gsap.to` that is not on a timeline. HyperFrames seeks only the timelines on `window.__timelines`, so put the tween on one of those to get the same picture in both.
- **Fonts.** Operating-system fonts are never read. CJK, Arabic, Devanagari and other scripts have no bundled font, so load one that has them.
- **Variable fonts** that set `font-variation-settings` per element can measure wider than in Chrome. A line fitted by `measureText` may then wrap.

The full list is in [Known issues](/docs/known-issues/#hyperframes-projects).
