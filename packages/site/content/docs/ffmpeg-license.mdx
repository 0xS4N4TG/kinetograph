---
title: FFmpeg licence
description: Which FFmpeg Kinetograph links, which one it runs as a separate program, and what licence each is under.
---

Kinetograph uses two FFmpeg builds, one to decode and one for some encoders. They are under different licences.

| | In the addon | The `bin/ffmpeg` program |
|---|---|---|
| What it is | Libraries linked into the native addon (`kinetograph.*.node`) | A stand-alone `ffmpeg` executable in the same npm package |
| FFmpeg licence | LGPL 2.1 or later | GPL 2 or later |
| Built by | `scripts/build-ffmpeg.sh` | `scripts/build-ffmpeg-gpl.sh` |
| Encoders | VideoToolbox (macOS), OpenH264 (macOS, Linux), Media Foundation (Windows), NVENC, libvpx (macOS, Linux), ProRes, AAC, GIF | libx264, libx265, libvpx, AAC |
| Used for | All decoding, and the default encoding | `libx264` and `libx265` only |

Libx264 and libx265 are GPL, and a GPL library cannot be linked into a PolyForm program. So the addon starts the GPL `ffmpeg` as a child process, sends it raw pictures on a pipe and reads a video file back. The two share no memory or code. The PolyForm licence does not cover `bin/ffmpeg`, and the GPL does not cover the addon.

## What ships in the package

Each `@kinetographdev/native-<platform>` package holds both licences and their texts (`LICENSE.md`, `FFMPEG-LICENSE.md`, `COPYING.GPLv2`, `COPYING.LGPLv2.1`), the `bin/ffmpeg` program (`bin/ffmpeg.exe` on Windows) and `bin/SOURCES.txt`, which lists the tag and commit of every library in it.

## Source code

The GPL program is built from unmodified upstream sources:

- FFmpeg 9.0.1 from [github.com/FFmpeg/FFmpeg](https://github.com/FFmpeg/FFmpeg), tag `n9.0.1`
- x264 from [code.videolan.org/videolan/x264](https://code.videolan.org/videolan/x264), a pinned commit of the `stable` branch
- x265 4.2 from [bitbucket.org/multicoreware/x265_git](https://bitbucket.org/multicoreware/x265_git)
- libvpx 1.15.0 (BSD-3-Clause) from [github.com/webmproject/libvpx](https://github.com/webmproject/libvpx)

The configure options and pinned refs are in [`scripts/build-ffmpeg-gpl.sh`](https://github.com/0xS4N4TG/kinetograph/blob/main/scripts/build-ffmpeg-gpl.sh). The LGPL build is [`scripts/build-ffmpeg.sh`](https://github.com/0xS4N4TG/kinetograph/blob/main/scripts/build-ffmpeg.sh).

## Use your own ffmpeg, or none

Set `KINETOGRAPH_FFMPEG` to any `ffmpeg` (for example `KINETOGRAPH_FFMPEG=$(which ffmpeg)`) to run it for encoders the addon lacks. That gives you `libx264` from your own build, or `h264_vaapi`, `hevc_vaapi`, `h264_qsv` and `hevc_qsv` on Intel and AMD GPUs.

Each encoder is looked up in your program first, then in the package's `bin/ffmpeg`, then in an `ffmpeg` on your `PATH` that lists it.

To keep the GPL program out of your install, delete `bin/ffmpeg` from the platform package. Renders then use the addon's encoders, and `--encoder libx264` and `--encoder libx265` fail with an error naming the missing encoder, unless `KINETOGRAPH_FFMPEG` or your `PATH` supplies one.
