---

Kinetograph renders Remotion projects without a browser. Your `remotion` and `@remotion/*` imports run on Kinetograph's own version of those packages, and the engine draws every frame itself.

Most projects just work. When something can't be drawn, Kinetograph tells you. For a package-by-package list with export counts, and the steps to move a project, see [Migrate from Remotion](/docs/guides/migrate/).

## What happens to things the engine can't draw

The engine skips them or draws something close, and prints a warning. It never switches to a browser.

- **Skipped:** the frame is drawn without the item.
- **Approximated:** the frame is drawn with something close to the item.
- **Warned:** after drawing, `render`, `still` and `strip` print one line for each kind of problem. Each line names the element, the property, the reason and the frames it happened on. At most 12 lines are shown, and nothing is printed if there were no problems.

The warning only appears on frames where the element is actually on screen. Elements with `display: none` or `visibility: hidden` are not checked.

### Make unsupported content an error with `--strict`

`render`, `still` and `strip` accept `--strict`. With it, the first frame that has anything unsupported stops the command with the error code `UNSUPPORTED_CONTENT`. The error exits with code 1, names the frame, and lists up to five items. A `render` that stops this way leaves no output file.

Use `--strict` in CI and for final renders, so you never ship a video with something missing. Without it, you get a video that may be slightly off, which is often more useful while you work.

`--strict` does not compare your video with Chrome. It only checks whether anything unsupported was used.

### Check a project before you render

- `kinetograph doctor <entry>` goes through every frame without using the GPU. It reports what the engine can't draw and on which frames. Run it before a long render. If the project imports a package Kinetograph doesn't support, such as `@remotion/three`, `doctor` lists each import and the file that has it, and still checks the frames it can.
- `kinetograph lint` adds one warning per problem, with rule `compat`. The frame still renders.
- Both are also MCP tools. The `doctor` tool takes the same arguments, and `still`, `strip` and `render` take `strict`.

`bench`, `onion` and `snapshot` draw frames as they are and do not warn. The studio shows a frame's unsupported items as a warning.

## What works

These packages and APIs are supported. Gaps are listed in [Known issues](/docs/known-issues/).

- `@remotion/transitions`: all 19 presentations and `useTransitionProgress`.
- `@remotion/light-leaks`, `@remotion/starburst`, `@remotion/sfx`, `zod-types`, `timeline-utils`, and `canvas` (Canvas 2D).
- `<canvas>` with a `webgl` or `webgl2` context, on the GPU with no browser: fragment shaders, framebuffers, points with `gl_PointSize`, instancing, `blitFramebuffer`, `texSubImage2D` and `gl_VertexID`. p5.brush's standalone build draws as it does in Chrome (its strokes, hatching and fills each differ by under 0.1 of 255 levels on average from Chrome). Lines, renderbuffers and depth testing are not drawn: see [Known issues](/docs/known-issues/).
- `@remotion/media-utils` audio: `getAudioData`, `useAudioData`, `useWindowedAudioData`, `getAudioDurationInSeconds`, `visualizeAudio` and `getWaveformPortion`. `visualizeAudio` follows Remotion's documented behaviour, but its numbers are not identical.
- `<Audio>` and `<Video>` from `@remotion/media`.
- `toneFrequency` on `<Audio>` and `<Video>`, from 0.01 to 2. It changes the pitch and keeps the length.
- `@remotion/media-parser` and `@remotion/webcodecs`: partly supported.
- `@remotion/skia` and `@remotion/rive`: run through optional add-ons, with gaps.
- GSAP (core, free plugins, `Flip`): a paused timeline that you seek to the frame's time, or a tween that plays by itself. See [GSAP](#gsap).
- `<Video datamosh>` is Kinetograph's own prop, not part of Remotion. See the [Datamosh guide](/docs/guides/datamosh/).

Plain HTML and SVG elements can sit next to Kinetograph's own elements in the same tree. You don't switch compatibility on.

### Things your project can use as it is

- `import './index.css'` works. Local `@import`s in the file are inlined. Tailwind is built with your project's own Tailwind setup. `*.module.css` files export their scoped class names.
- The entry file runs even when `package.json` has a `"sideEffects"` list that leaves it out, as Remotion's templates do.
- `staticFile` reads `public/` next to the entry. If there is none, it reads `public/` next to the nearest `package.json`, which is Remotion's rule when the entry is in `src/`.
- Fonts load from their files, whether you add them with `new FontFace(...)` and `document.fonts.add(face)` or with an `@font-face` rule. One file is kept for each family, weight and style. If a font is split by `unicodeRange`, the part covering basic Latin is used. WOFF and WOFF2 files are unpacked.
- HTML text can have an outline: `-webkit-text-stroke` (and its width and colour longhands) is drawn with the same miter joins as Chrome, and `paint-order: stroke fill` puts the stroke under the fill, as caption styles do. Both work with `text-shadow` (the shadow is stroked too), transforms, opacity and `background-clip: text`.
- Kinetograph reads no fonts from your system, so a render looks the same on every machine. If your project loads no font, text is drawn in DM Sans, a font that ships with Kinetograph, and the warning and `doctor` say so (`font-family`, "font not loaded; drawn with the built-in fallback"). SVG `<text>` is covered too.

### GSAP

GSAP (core and the free plugins) works on the page's elements and SVG. Build a paused timeline in a layout effect and seek it to the frame, which is the pattern Remotion documents:

```tsx
const frame = useCurrentFrame();
const { fps } = useVideoConfig();
const tl = useRef<gsap.core.Timeline>(null);
useLayoutEffect(() => {
  const t = gsap.timeline({ paused: true });
  t.to(box.current, { x: 600, rotation: 45, backgroundColor: '#e0261b', duration: 1 });
  tl.current = t;
  return () => { t.kill(); };
}, []);
useLayoutEffect(() => { tl.current?.seek(frame / fps); }, [frame, fps]);
```

- Tweens of `x`, `y`, `rotation`, `scale`, `skew`, `opacity`, colours, `width`, `height`, `borderRadius`, `boxShadow`, `filter`, `clipPath`, `letterSpacing` and the rest of the CSS the engine draws. Units such as `x: '50%'` are measured on the page.
- SVG: `attr` (`cx`, `r`, `d`), `strokeDashoffset`, `fill`, and transforms (GSAP writes the `transform` attribute).
- `TextPlugin`, `SplitText`, `DrawSVGPlugin`, `MotionPathPlugin` and `CustomEase`. `onUpdate` callbacks that write `textContent` work when you seek with `suppressEvents` set to `false`.
- A frame renders the same by itself as in a full render, since a seek does not depend on time.
- A tween that plays by itself works too: `gsap.to(...)` in a `useEffect`, with no paused timeline. GSAP's root clock is moved with the frame: Kinetograph takes the root timeline off GSAP's ticker (`gsap.ticker.remove(gsap.updateRoot)`), turns lag smoothing off, and calls `gsap.updateRoot(seconds)` with the frame's time before each frame renders. Nothing of GSAP is patched. The CLI finds your copy of GSAP when you `import 'gsap'` (or `'gsap/all'`); a page that loads GSAP's browser build, as a HyperFrames page does, is found at `window.gsap`. A tween made in an effect at frame 30 starts at frame 30, which is where a render of every frame has it; checked against Chrome (a paused timeline with the tween placed at 1 s), the mean difference is 0.02 at frames 30, 45 and 59.
- A frame is the same alone as in a full render, and at any `--concurrency`. A jump to a later frame renders the frames it skips (nothing is drawn or read from them) so that an effect which makes a tween at frame 30 has run. A scene that starts over (going back a frame) keeps the tweens already made, as it keeps `requestAnimationFrame` callbacks, and the clock goes back with it: stop a tween in the effect's cleanup (`return () => tween.kill()`) so it does not outlive the scene.
- A paused timeline that you seek yourself is not on the root clock and renders as before.
- A read of the layout that the engine can't answer is a warning, and GSAP gets the element's own style.
- `Flip` works: `Flip.getState(...)`, a change to the layout, then `Flip.from(...)` on a paused timeline seeked to the frame renders as it does in Chrome (mean difference 0.00 at frames 0, 15, 30, 45 and 59).
- `ScrollTrigger` and `Draggable` respond to scrolling and dragging, which a render does not have, so they do not apply.

## HyperFrames projects

`kinetograph render`, `still`, `doctor` and `studio` take a [HyperFrames](https://github.com/heygen-com/hyperframes) project as it is: pass its `index.html`, or the directory that holds it. There is no rewrite. Nothing runs in a browser.

```sh
kinetograph fetch-deps my-video        # once: downloads the CDN scripts the page loads
kinetograph render my-video -o out.mp4
```

- **Size and time.** The root `data-composition-id` element gives the size (`data-width`, `data-height`) and length (`data-duration`, else the longest timeline or clip). The rate is 30 fps, as in HyperFrames.
- **Clips.** An element with `data-start` shows from its start for `data-duration`, then is hidden, as HyperFrames does. `data-start` takes seconds or `clip-id`, `clip-id + 2`, `clip-id - 0.5`. A video or audio without `data-duration` lasts its file. An `<img>` with only `data-start` lasts 3 s.
- **Compositions.** `data-composition-src` mounts the file's `<template>` into the host. The file's CSS is scoped to the composition, and its script sees only that composition (`document.querySelector`, GSAP string targets). `data-variable-values` and `getVariables()` work.
- **Timelines.** Every frame, each `window.__timelines` entry is paused and seeked to its time: the root to the frame's time, the others to their host's local time (`data-playback-start`, `data-playback-rate`), held at both ends. A frame depends only on its number.
- **Media.** `<video>` is decoded and drawn by the engine, frame-accurate, with `data-media-start` and `data-playback-rate` (`"2x"` is 2; kept to 0.1 to 10). `<audio>` and a `<video>` that is not `muted` (and has no `data-has-audio="false"`) are mixed, with `data-volume`, `data-fade-in` and `data-fade-out`. A media element inside a composition whose host has an in-point (`data-playback-start`) has its origin at the host's start less the in-point and is cut to the host's window; `data-hf-media-start-basis="global"` keeps a start that is already the project's. The host's own `data-playback-rate` moves its timeline only, as in HyperFrames.
- **`data-hidden`.** A clip with `data-hidden` is taken out of the picture (`display: none`, the author's value back when the flag goes) and its audio, and that of anything inside it or in a hidden `<hf-audio-group>`, is dropped from the mix.
- **Speed ramps and volume lanes (`data-automation`).** A `rate` lane (breakpoints in the clip's own seconds, with `curve` or `viaX`/`viaY` shaping) sets the file's time to the integral of the rate for a `<video>`, the local time of a composition host's timeline, and the length of a clip without a `data-duration`. A `volume` lane multiplies `data-volume` (capped at +12 dB) and replaces nothing else: fades and the group's `data-volume` and lane still apply. Audio plays a ramped file in quarter-second slices, each at the mean rate of its slice. HyperFrames has no pan lane; `fx.*` lanes drive audio effects, which are ignored.
- **Colour grading (`data-color-grading` on `<video>`, `<img>`, `<canvas>`).** Drawn as an SVG filter, so it runs in the engine and not in a browser. Exact (one colour matrix): `exposure`, `contrast`, `blacks`, `whites`, `temperature`, `tint`, `saturation`, and `intensity` as the mix with the source. Within the 32 values of a filter table: `curves`. Approximated, and reported on every frame: `shadows`, `highlights`, the three `wheels` (HyperFrames weights them by each pixel's luma; here the channel stands in for it, exact for greys) and `vibrance`. Not drawn, and reported: `lut` (the engine has a `.cube` effect, but a DOM node cannot reach it), `hueCurves`, `secondaries`, `details` (vignette, grain) and `effects`. `--hf-color-grading-intensity`, `-lut-intensity` and `-exposure` set inline by a tween are followed. Presets by name work.
- **Fonts.** A page that names one of the 18 families HyperFrames embeds (Inter, Montserrat, Outfit, Nunito, Oswald, League Gothic, Archivo Black, Space Mono, IBM Plex Mono, JetBrains Mono, EB Garamond, Playfair Display, Source Code Pro, Noto Sans JP, Roboto, Open Sans, Lato, Poppins), or an operating-system name HyperFrames maps to one, gets that family in every weight Google serves, under the name the page used. As in HyperFrames, `Arial`, `Helvetica`, `Verdana`, `Calibri` and the other sans-serif system names are Inter (not a metric clone of Arial), `Consolas`, `Menlo`, `Courier New` and the other monospace ones are JetBrains Mono, and `Georgia`, `Times New Roman` and `Palatino` are EB Garamond. An `index.html` that is a fragment is wrapped as HyperFrames wraps it: margins and padding reset, black body, Inter. The files come from the font cache that `fetch-deps` fills; a render never downloads a font. Operating-system fonts are never read.
- **Scripts.** Classic scripts share top-level `const`, `let` and `class` as in a browser. A page with no `data-duration` runs its scripts with layout (in a root of their own, before the first frame). A page's `<template>` keeps its content out of the document; `template.content.cloneNode(true)` is an `hf-fragment` element with `display: contents`. `@media` rules that reach into an `<svg>` are applied where the query holds for the composition's size.
- **Seeking.** GSAP timelines are seeked as HyperFrames' runtime seeks them: a timeline that has never rendered is rendered at 0, and the root is rendered again from just below the instant so that steps at one time apply in authored order.
- **Scripts from a CDN are never fetched while rendering.** A URL on jsdelivr or unpkg resolves to the same package and version in a `node_modules` at or above the project; otherwise to `~/.cache/kinetograph/cdn`, which only `kinetograph fetch-deps <entry>` fills. If neither has it, the command stops and names the URL and `fetch-deps`. `fetch-deps` downloads over https from `cdn.jsdelivr.net`, `unpkg.com`, `cdnjs.cloudflare.com` and `esm.sh` only (`--allow-host` adds one), checks a script tag's `integrity`, and a render checks the hash it stored before running the file. Local `<script src>` files load from disk. Google Fonts `<link>`s load through the font cache.
- **Data and media from the web.** `fetch-deps` also downloads the `https` files a script names on the same hosts (`d3.json("https://cdn.jsdelivr.net/npm/world-atlas@2/countries-110m.json")`; `--url` adds one a scan missed, which `doctor` lists when a render refused it) and the remote `<video>`, `<audio>` and `<source>` files the page plays (500 MB each, `--max-media-mb`). They follow the script rules: https only, the default hosts plus `--allow-host` (a host the page names is not allowed by naming it), no redirect off the list, a hash stored and checked on every read. `fetch()` of exactly such a URL reads the cache, and the frame waits for what the page fetched at load. A file that is not cached is a clear error on `fetch` and a note on every frame for media, never a silent blank.
- **Remote pictures.** `fetch-deps` also downloads the `https` pictures the page names: `<img src>` (or the `srcset` candidate a browser would take: 1x, else the smallest density above it, else the first), `<video poster>`, an SVG `<image href>`, and `url()` in `background`, `mask`, `border-image`, `list-style`, `content`, `shape-outside` and custom properties, in stylesheets, `<style>` and inline `style`. `http:` is refused, `data:` and relative paths are not remote. They follow the media rules (default hosts plus `--allow-host`, no redirect off the list, a hash stored and checked on every read) with a 50 MB cap each. A picture that is not cached is drawn without and reported on every frame with the command to run, for example `kinetograph fetch-deps index.html --allow-host www.transparenttextures.com`; `--strict` fails on it. A script that sets a picture at run time (`el.style.backgroundImage = "url(https://...)"`) is not scanned.
- **WebGPU shaders.** A page that draws with WebGPU (the `shaders.iife.js` blocks: `aurora`, `blob`, `ripples`, `swirl`, ...) is drawn natively. `hf-seek` events carry the frame's time, and the frame waits for the page to answer `waitUntil`. The body has no margin, as in HyperFrames. What a page asks of WebGPU that is not drawn is reported on every frame; see [Known issues](/docs/known-issues/#webgpu).
- **Unsupported.** Three.js and import maps are reported on every frame (`--strict` fails). See [Known issues](/docs/known-issues/#hyperframes-projects).

## Libraries

Third-party libraries run unchanged on the engine's DOM, as long as the frame is what a seek or the frame number says. Checked against Chrome stills at frames 0, 30 and 59 (mean per-channel difference, 0 to 255, in brackets).

- **d3** (scale, shape, selection): d3 makes the paths and React draws them, or `d3-selection` appends to a ref, including `join()` and `order()` (under 0.2).
- **rough.js**: the SVG and Canvas 2D generators (under 0.5).
- **Paper.js**: `paper-full` on a canvas (under 0.2). The bundle reads a package's `browser` map for imports that don't resolve (Paper.js drops `jsdom` and `canvas` there).
- **Chart.js**: line charts on a canvas (under 1.4). Load a font before the chart, or it uses the built-in one.
- **Recharts**: SVG charts with `isAnimationActive={false}` (under 0.3). Pass a fixed `width` and `height`. Recharts draws its marks through `createPortal`, which places children into the element a ref gave and into `document.body`.
- **visx**: shapes, scales and axes (under 0.5).
- **anime.js** v4: build a paused timeline and `seek(ms)` it to the frame (under 0.03).
- **Motion**: vanilla `animate()` with `controls.time = seconds` on a paused animation, and `motion.div` with style values (under 0.4). Colours come from Motion's own mixing, which differs a little from the browser's. See [Libraries that run their own frame loop](#libraries-that-run-their-own-frame-loop).
- **Matter.js** and **Rapier** (`@dimforge/rapier2d-compat`, WASM embedded): step the world from the frame number (under 0.2). A `delayRender` opened while the module loads holds frame 0 like any other frame.
- **`@remotion/motion-blur`, `layout-utils` and `captions`** (under 1.1).
- **Bklit UI** (visx, d3 and Motion charts): layout, animation timing, text and colours (`var()`, `oklch()`, `color-mix()` in SVG paint) match Chrome. Line, bar, pie and geo charts are under 0.15 once their entry animation has played.

Also available to libraries: `NodeList` and `HTMLCollection` as real classes, `HTMLElement` and `SVGElement` that tell the two apart, `compareDocumentPosition`, `document.defaultView`, `customElements`, `setAttributeNS` and its siblings, lookups of nodes appended to `document.body`, and SVG text `getBBox` and `getComputedTextLength` from the text engine.

### Libraries that run their own frame loop

`requestAnimationFrame` callbacks run once per frame with the frame's time, after the frame has rendered. A jump to a frame (a still, or a worker starting at frame 600) runs them through the frames it skips without rendering those, so a library that advances by the time between frames, such as Motion's mount animations, shows the same pixels in a still as in a render of every frame. Two limits:

- Motion's frame loop clamps each step to 40 ms, so below 25 fps its animations run a little slow.
- A scene that starts over (going back a frame) keeps the callbacks already asked for, because the library's own state outlives it. A loop of your own should cancel its `requestAnimationFrame` in the effect's cleanup.

## Layout of HTML content

CSS lays out HTML content the same way a browser would, with a few rules to know:

- A group of HTML elements is laid out as a box the size of the composition, as Remotion's root `div` is.
- An `<AbsoluteFill>` or `<Sequence>` around HTML is an absolutely positioned column flex `div`, as in Remotion.
- HTML inside a Kinetograph layer is laid out in the composition's box. It does not know the layer's own size.
- A Kinetograph element inside HTML takes the size of its own box. A layer with no box, such as a group without `layout`, is 0 × 0. A `<GlslShader>` in the flow takes its `width` and `height` as a box, like an `<Image>`, and takes up that room.
- Styles are read on every frame, so animation comes from your component re-rendering, as in Remotion. CSS `@keyframes` follow the frame's time.
- A layer made from an HTML node takes its `id` attribute as its layer id if that is a valid id. Otherwise it gets where the node sits in the page, such as `$0.2`.

<Accordion title="How a frame is drawn">

1. The React tree runs for the frame. HTML elements (`div`, `span`, `svg` and the rest) keep their props, as Kinetograph's own elements do.
2. Each outermost run of HTML elements is a DOM island. Its tags, attributes, inline styles, stylesheets and the frame's time go to the Rust engine.
3. The engine styles the island with Stylo (Firefox's CSS engine), lays it out with taffy, and shapes its text with Parley. It paints the result in CSS paint order.
4. Kinetograph's own elements inside an island are placed in the boxes that layout gives them.
5. Anything the painter can't draw is reported for that frame.
6. Every frame is drawn in order on the GPU and encoded.

Each top-level layer an island produces is absolutely positioned, so a flex parent outside the island does not move it again.

<Accordion title="The shape of the warning data">

With `--json`, stderr stays quiet and the full list is in the result as:

```ts
compat: {
  unsupportedFrames,
  leftOut: [{ element, property, reason, values, frames, firstFrame, lastFrame }]
```

The text output of `render` adds `unsupported content left out of N frames`.

Internally, each unsupported item looks like this:

```ts
interface Unsupported {
  path: string;            // where the element sits in the page and its tag: '$0.2.1 <div>'
  element: string;         // 'div', 'svg > text', …
  property: string | null; // 'transform'; null for an unsupported element
  value: string | null;
  reason: string;
}
```

<Accordion title="The shape of the doctor report">

`kinetograph doctor <entry> [--comp] [--props] [--range] [--json]` runs the JavaScript stage for every frame in the range, without the GPU.

```ts
interface DoctorReport {
  comp: string; first: number; last: number; frames: number;
  cleanFrames: number;          // frames with nothing unsupported: drawn in full
  unsupportedFrames: number;    // frames with at least one unsupported item
  cleanShare: number;           // 0..1
  issues: DoctorIssue[];        // most frames first
  notes?: string[];             // problems with the project's stylesheets that no frame shows (Tailwind that could not be built, …)
}

interface DoctorIssue {
  element: string; property: string | null; reason: string;  // the group key
  values: string[];                          // distinct values seen, at most 5
  paths: string[];                           // distinct element paths, at most 5
  ranges: [first: number, last: number][];   // inclusive, ascending
  frames: number;
}
```

<Accordion title="glTF models">

If a `<Model>` file (or a `model` object's file) uses something the 3D layer can't read, it is listed like any other unsupported item, on every frame that draws the model. The element is `Model`, the property is the feature (for example `KHR_materials_clearcoat` or `normal textures`), and the value is the file.

The CLI asks the addon once for each file. A file it can't read at all is not listed. The render fails on it instead. The scene format is described in [SCENE.md](https://github.com/0xS4N4TG/kinetograph/blob/main/packages/cli/skills/kinetograph/references/SCENE.md).
