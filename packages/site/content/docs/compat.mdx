title: Remotion compatibility

Kinetograph renders Remotion projects without a browser. `remotion` and `@remotion/*` imports resolve to Kinetograph's own implementation, rebuilt from Remotion's documented behaviour. A project is bundled as it is, and every frame is drawn by the engine. The engine never uses a browser to draw a frame.

Compatibility is not a switch. Plain HTML and SVG elements can sit next to Kinetograph's own elements in the same tree, and a project that uses them renders as it is. What the engine cannot draw is reported, and left out or approximated. See [Unsupported content](#unsupported-content).

## How a frame is drawn

1. The React tree is run for the frame. DOM elements (`div`, `span`, `svg` and the rest) keep their props, as Kinetograph's own elements do.
2. Each outermost run of DOM elements is a DOM island. Its tags, attributes, inline styles, stylesheets and the frame's time are passed to the Rust engine.
3. The engine styles the island with Stylo, which is Firefox's CSS engine, lays it out with taffy and shapes its text with Parley. It paints the result in CSS paint order.
4. Kinetograph's own elements inside an island are placed in the boxes that layout gives them.
5. Anything the painter cannot draw is reported for that frame.
6. Every frame is drawn in order on the GPU and encoded.

## What a project can use as it is

- `import './index.css'` is read. The file's text, with its local `@import`s inlined, becomes a stylesheet of the document. Tailwind is built with the project's own Tailwind setup. `*.module.css` files export their scoped class names.
- The entry file runs even when `package.json` lists `"sideEffects"` without it, as Remotion's templates do.
- `staticFile` reads `public/` beside the entry. If there is none there, it reads `public/` beside the nearest `package.json`, which is Remotion's rule when the entry is in `src/`.
- `<Audio>` and `<Video>` from `@remotion/media` are Kinetograph's own.
- A font registered with `new FontFace(...)` and `document.fonts.add(face)`, or with an `@font-face` rule in a stylesheet, is loaded from its file. One file is kept per family, weight and style. Of a face split by `unicodeRange`, the part covering basic Latin is used. WOFF and WOFF2 files are unpacked.

## Layout of DOM content

- A DOM island is laid out as CSS lays out a box the size of the composition, as Remotion's root `div` is.
- An `<AbsoluteFill>` or `<Sequence>` wrapper around DOM is an absolutely positioned column flex `div`, as in Remotion. It is laid out in the same island as the DOM around it.
- A DOM island inside a Kinetograph layer is laid out in the composition's box. The island does not know the layer's own layout box.
- Each top-level layer an island produces is absolutely positioned, so a flex parent outside the island does not move it again.
- A Kinetograph element inside DOM is a replaced box the size of its own box. A layer with no box, such as a group without `layout`, is 0 × 0. It is placed by CSS and drawn as it is.
- DOM styles are read at each frame, so animation comes from the component re-rendering, as in Remotion. CSS `@keyframes` read the frame's time.
- Layers made from a DOM node take ids from it: its `id` attribute if that is a valid layer id, otherwise its position in the tree, such as `$0.2`.

## Supported packages and APIs

These packages and APIs are supported. Gaps in any of them are listed under [Known issues](/docs/known-issues/).

- `@remotion/transitions`: all 19 presentations and `useTransitionProgress`.
- `@remotion/light-leaks`, `@remotion/starburst`, `@remotion/sfx`, `zod-types`, `timeline-utils`, and `canvas` (Canvas 2D).
- `@remotion/media-utils` audio: `getAudioData`, `useAudioData`, `useWindowedAudioData`, `getAudioDurationInSeconds`, `visualizeAudio` and `getWaveformPortion`. `visualizeAudio` follows Remotion's documented behaviour, not its exact numbers.
- Pitch: `toneFrequency` on `<Audio>` and `<Video>`, from 0.01 to 2, changes the pitch and keeps the length.
- `@remotion/media-parser` and `@remotion/webcodecs`: partly supported. See Known issues.
- `@remotion/skia` and `@remotion/rive`: run on the engine through optional add-ons, with gaps. See Known issues.

## Unsupported content

Every frame is drawn by the engine. The engine reports what it could not draw as a browser would. That item is drawn without, or approximated. There is one drawing path, so no frame or scene is switched to another renderer.

```ts
interface Unsupported {
  path: string;            // the element's host-tree path and tag: '$0.2.1 <div>'
  element: string;         // 'div', 'svg > text', …
  property: string | null; // 'transform'; null for an unsupported element
  value: string | null;
  reason: string;
}
```

- **Warnings.** `render`, `still` and `strip` print one line per kind of unsupported content to stderr after drawing, with the element, property, values, reason and frames. At most 12 kinds are listed, and nothing is printed when there is none. With `--json`, stderr stays quiet and the full list is in the result as `compat: { unsupportedFrames, leftOut: [{ element, property, reason, values, frames, firstFrame, lastFrame }] }`. The text output of `render` adds `unsupported content left out of N frames`.
- **`--strict`.** `render`, `still` and `strip` accept `--strict`. The first frame that holds an unsupported item fails the command with the error code `UNSUPPORTED_CONTENT`. The error exits with code 1, like every error, names the frame and lists up to five items. `render` aborts, so no output file is left. The check runs as the frames are drawn, so a `--strict` render stops at the first bad frame rather than at the end.
- **Default.** Without `--strict`, an approximate video is often more useful than none. CI and finished projects can pass `--strict` to keep their output exact.
- **Other commands.** `bench`, `onion` and `snapshot` draw as they are and do not warn. The studio shows a frame's unsupported items as a warning.
- **What counts.** An item counts only on frames where its element is in the tree. Subtrees with `display: none` and boxes with `visibility: hidden` are not checked.
- **glTF models.** What a `<Model>` file (or a `model` object's file) uses that the 3D layer does not read is listed like the above, on every frame that draws the model. The element is `Model`, the property is the feature (for example `KHR_materials_clearcoat` or `normal textures`), and the value is the file. The CLI asks the addon once for each file. A file it cannot read is not listed, and the render fails on it instead. The scene format is described in [SCENE.md](https://github.com/0xS4N4TG/kinetograph/blob/main/docs/SCENE.md).

## Checking a project with doctor

`kinetograph doctor <entry> [--comp] [--props] [--range] [--json]` runs the JavaScript stage for every frame in the range, without the GPU, and reports what the engine cannot draw and in which frames. Run it before a long render.

```ts
interface DoctorReport {
  comp: string; first: number; last: number; frames: number;
  cleanFrames: number;          // frames with nothing unsupported: drawn in full
  unsupportedFrames: number;    // frames with at least one unsupported item
  cleanShare: number;           // 0..1
  issues: DoctorIssue[];        // most frames first
  notes?: string[];             // problems with the project's stylesheets that no frame shows (Tailwind that could not be built, …)
}

interface DoctorIssue {
  element: string; property: string | null; reason: string;  // the group key
  values: string[];                          // distinct values seen, at most 5
  paths: string[];                           // distinct element paths, at most 5
  ranges: [first: number, last: number][];   // inclusive, ascending
  frames: number;
}
```

- **lint.** `kinetograph lint` adds one finding per issue group, with rule `compat` and severity `warning`. The frame still renders, without the item or approximated.
- **MCP.** The MCP server has a `doctor` tool with the same arguments. `still`, `strip` and `render` take `strict`.
