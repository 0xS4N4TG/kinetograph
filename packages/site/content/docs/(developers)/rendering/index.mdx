title: Rendering
description: Look at single frames while you work, check the project, and render it to an MP4 or a sequence of images.
---

Look at frames with `still` and `strip`, check them with `lint` and `doctor`, then `render` the video. Every command takes the entry file, and an HTML page works the same way.

```sh
npx kinetograph strip src/index.tsx -n 12
npx kinetograph render src/index.tsx
```

The video goes to `out/renders/<composition id>.mp4`. Pass `-o` to choose another path.

- `still` writes one frame as a PNG.
- `strip` writes evenly spaced frames on one sheet, labelled with the frame and the time. Start here: it shows the whole animation.
- `onion` blends the frames of a range over one another, to show a motion path.

A frame is a whole number from 0. A range `10..40` is frames 10 to 39.

## Check the project

```sh
npx kinetograph inspect src/index.tsx --frame 30
npx kinetograph lint src/index.tsx
npx kinetograph check src/index.tsx
npx kinetograph doctor src/index.tsx
```

- `lint` reports overflowing text, layers off the canvas, and missing fonts and assets.
- `check` finds type errors, such as a misspelled prop.
- `doctor` lists what the engine cannot draw, and on which frames. Run it before a long render. See [What works](/docs/compat/#when-the-engine-cant-draw-something).

## Render

```sh
npx kinetograph render src/index.tsx --draft
npx kinetograph render src/index.tsx --range 0..90 --strict
```

- `--draft` renders at half size, for a quick look.
- `--range a..b` renders only those frames, and the audio for them.
- `--strict` stops at the first frame with something the engine cannot draw, and leaves no file. Use it for final renders and in CI.
- `--comp <id>` and `--props '{"title":"Hello"}'` pick the composition and its props.

## Check the render

The command prints a summary: size, codec, encoder, pixel format, frames, how many were `repeated` (identical to the one before, so not drawn again), and a `renderer:` line. `Skia GPU` is fast. `Skia CPU` means the GPU was not used and the render will be slow; `doctor` says why. With `--json`, `output` is the file and `compat` lists what was left out.

For a long film, `strip` a range or render with `--draft --range` first. Check the sound with `audio analyze`, and check transparency by opening a `--sequence` PNG.

## Transparent video

A video keeps transparency only with an alpha pixel format, and only where the frame has no opaque background. A composition with no `background` is transparent.

- ProRes: `--codec prores --prores-profile 4444 --pixel-format yuva444p10le`, to a `.mov`. The 4444 profiles drop alpha unless the pixel format asks for it.
- VP9: `--codec vp9 --pixel-format yuva420p`, to a `.webm`.

Alpha is written straight, not premultiplied. Players handle alpha, 4:2:2, 4:4:4 and 10-bit unevenly, and 8-bit 4:2:0 plays everywhere.

## Export options

`--codec h264|h265|prores|vp9|gif` and the extension (`.mp4`, `.mov`, `.webm` or `.gif`) set the format. The other flags are in the [CLI reference](/docs/reference/cli/#render).

`--sequence` writes one image per frame into the `-o` folder instead of a video, as `png` (with alpha) or `jpeg`. A sequence has no audio.

## What works

- Drawn natively: everything listed under [Making videos](/docs/making-videos/compositions/), on the GPU with no browser.
- Approximated or left out: a frame with content the engine cannot draw is drawn without it, or close, and the command prints one warning line for each kind of problem. `--strict` makes it an error.
- Not supported: a render in a cloud function. There is no cloud renderer, so run `render` on a machine with a GPU.
- See [What works](/docs/compat/) for the full list.
