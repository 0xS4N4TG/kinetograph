Each item says what doesn't work and what you see instead. For what does work, see [Remotion compatibility](/docs/compat/).

Items marked "reported" show up in the render warnings and in [`doctor`](/docs/terminology/doctor/). With `--strict`, they fail the render.

## Not planned

- `IFrame` is not drawn, because a real webpage needs a browser. It is reported.
- `Internals`, `FolderContext`, `PathInternals` and `AudioForPreview` are internal to Remotion and not exported.
- `@remotion/three` and `@remotion/player` are replaced by the engine's own 3D layer and studio.
- `renderer`, `bundler`, `cli` and `lambda` are replaced by the Kinetograph CLI.
- `tailwind` and `tailwind-v4` only configure webpack, so they do nothing. Tailwind itself works.

## Partly working

### Text and fonts

- A character the font lacks falls back to Noto Sans Symbols 2, Noto Sans Math or Noto Emoji. Emoji are monochrome.
- CJK, Arabic, Devanagari and similar scripts have no bundled font. They are drawn as boxes and reported. Load a font that has the characters.
- `monospace` text falls back to a proportional face, so code blocks (Shiki, Code Hike) look wider than in Chrome. Load a monospace font, for example `@remotion/google-fonts/JetBrainsMono`.
- The `ex` unit uses the first font's x-height. With only a generic family such as `serif`, that is the built-in fallback, so a MathJax formula comes out about 10% larger. Load the font the page asks for.
- `ex` in SVG shape attributes (`<rect width="10ex">`) is half an em.

### Video pixels

`onVideoFrame` on `<Video>`, `<OffthreadVideo>` and `<Html5Video>` hands your code the frame the video shows. Draw it with `drawImage` and read it with `getImageData`. These limits apply:

- The frame is not a WebCodecs `VideoFrame`. It has `width`, `height`, `timestamp` and `close()` only.
- A canvas you draw on starts each frame empty.
- A video with no named colour space is converted differently from Chrome.
- The frame of a `<video>` element you create is the one at its `currentTime`. The engine does not play it.
- The `onVideoFrame` of `@remotion/webcodecs` `convertMedia` is a different API and still throws.

### WebCodecs

Encode and decode functions in `@remotion/webcodecs`, and the box tree and sample callbacks of `@remotion/media-parser`, throw `UnsupportedApiError`. Normal `<Video>` and `<Audio>` are not affected.

### Hardware encoding on Linux

The addon's ffmpeg has no VAAPI or Quick Sync encoders. Run them in your system's ffmpeg:

```sh
KINETOGRAPH_FFMPEG=$(which ffmpeg) npx kinetograph render scene.json -o out.mp4 --encoder h264_vaapi
```

- Supported: `h264_vaapi`, `hevc_vaapi`, `h264_qsv` and `hevc_qsv`, for `yuv420p` (and `yuv420p10le` for `hevc_*`).
- They are never the default. Without the flag, Linux renders with `libopenh264`.
- VAAPI uses the first `/dev/dri/renderD*`. Set `KINETOGRAPH_VAAPI_DEVICE=/dev/dri/renderD129` to pick another.
- Output depends on the GPU and driver. `--crf N` maps to the encoder's constant quality, which is not the same picture quality.
- Not yet tried on real hardware. If it fails, report the error and `ffmpeg -encoders | grep -E 'vaapi|qsv'`.

### Effects and `HtmlInCanvas`

- `2d`, `webgl2` and `webgpu` effects, `onPaint` and `onInit` run. A call that [WebGPU](#webgpu) lists as not drawn leaves the frame without the effect and is reported.
- State kept from `setup` does not carry to the next frame. Each frame runs `setup`, `apply` and `cleanup` again.
- `getImageData` of the source is not supported.
- An `<HtmlInCanvas>` inside another is not supported.
- An `async` `apply`, `onInit` or `onPaint` holds the frame until its promise settles. `setTimeout` waits do not work.

### Canvas 2D

- A `url()` filter works when it names an SVG `<filter>` of the page. On a `<Canvas>` component it is reported.

### WebGL

Every frame starts with an empty canvas, also with `preserveDrawingBuffer`, because a frame is a function of its own number. These are not supported:

- Multisampled renderbuffers and edges.
- `readPixels`.
- `LINES`, `LINE_STRIP` and `LINE_LOOP`.
- Instanced points, and a `vertexAttribDivisor` above 1.
- Cube, 3D and float textures, and `sampler2DShadow`.
- Render targets that are not RGBA, and attachments of different sizes in one framebuffer.
- `generateMipmap` on a texture that was drawn into, and a `TEXTURE_BASE_LEVEL` other than 0.

Depth, stencil and points work, with these differences from a browser:

- The depth buffer holds 32-bit floats, not 24 bits, so very close surfaces can order differently.
- A canvas made with `depth: false` has no depth buffer, so the depth test always passes.
- A depth texture is sampled `NEAREST`.
- Points are squares of at most 511 pixels.
- `gl_VertexID` with `drawElements` is the position in the index list, not the index.
- `texSubImage2D` over a mipmapped texture rebuilds the mipmaps. Chrome keeps the old levels.

### WebGPU

A canvas's `getContext('webgpu')` records its calls, and the passes it submits are drawn on the engine's own device. Supported:

- Buffers, WGSL modules, render and compute pipelines, bind groups, and render and compute passes.
- 2D textures in the 8, 16 and 32-bit colour formats that need no optional feature, with storage buffers and storage textures.
- Texture uploads and copies. `copyExternalImageToTexture` takes images, `ImageBitmap`, canvases, `<video>` and effect layers, and writes the four 8-bit RGBA formats only.
- Multi-pass shaders that render into textures.

Not supported, reported on every frame:

- Query sets and timestamp writes, render bundles, indirect draws and dispatches.
- Depth and stencil, multisampling, texture arrays, 1D and 3D textures, comparison samplers, `viewFormats`.
- `importExternalTexture`. Use `copyExternalImageToTexture` instead.
- Reading a buffer or texture back (`mapAsync`, `copyTextureToBuffer`).
- The canvas's own texture as a source, and pipeline-overridable constants.
- Depth, compressed and optional-feature texture formats.

Things to know:

- An `rgba16float` or `display-p3` canvas is clipped to SDR sRGB. `toneMapping: { mode: 'extended' }` is drawn as standard and reported.
- A WGSL module that naga or wgpu refuses gives a warning and a transparent canvas.
- A frame holds at most 4 GiB of textures, 4096 steps and 4096 dispatches. Going over gives a warning and a transparent canvas.
- `atomic` operations whose result depends on invocation order are not deterministic on a GPU, and the engine does not change that.

**State across frames.** A texture or buffer that a pass builds on from the earlier frame (a simulation with `loadOp: 'load'`) is replayed from its history, so it is right in a sequence. A frame drawn alone, or by another worker, cannot have that state. Each frame that reads such state is reported, and `doctor` lists it.

To make a frame the same alone as in a sequence, clear or rewrite what a compute pass writes before using it. A compute pass does not count as a full write. Bind only what a pass uses, because an unused read-write storage buffer is kept as a dependency of every later frame.

### WGSL `shader()`

It sees only its own layer, runs one pass, has no other texture, and takes `f32` uniforms only.

### 3D (`scene3d`)

- A texture on a second set of texture coordinates, `alphaMode: MASK` (drawn opaque) and glTF extensions are not read, and are reported.
- A scene's shadow maps may hold at most 1 GiB, counted at the largest `mapSize` (48 maps of 2048 or 16 of 4096). A point light takes 6 maps. A scene over the limit is refused when it loads.

### CSS and SVG

- A `backdrop-filter` in a `preserve-3d` context, inside an element drawn as one group (`opacity` below 1, `filter`, `mask`, `mix-blend-mode`, `isolation: isolate`), blurs only what its own 3D context drew. Chrome blurs everything the group drew. It is reported as approximated.
- A basic shape such as `inset()` as `clip-path` on an element inside an `<svg>` is not drawn.
- A rule that sets a property to its initial value does not win over a presentation attribute. `.bar { fill: black }` over `fill="red"` stays red.

### Libraries

- **Mermaid 12** draws flowcharts, class, state, entity-relationship, sequence and pie diagrams. Register your font before `mermaid.render`. A `<foreignObject>` with a percentage `width` or `height` is not drawn. `mermaid.initialize({ htmlLabels: false })` gives plain SVG text.
- **Chart.js, Recharts and others** measure text with the fonts you registered. With none registered, they use the built-in font.
- **Motion** components that mount mid-video, in a `<Sequence>`, start their animation at the frame they mount on. A still, or a worker that starts later, starts the animation at its own first frame. Mount them at frame 0, or drive them with `@kinetographdev/motion`.
- **Web Animations** (`element.animate()`): a pseudo-element animation (`pseudoElement: '::before'`) is not drawn and warns once.
- A library that reads the wall clock or a real `Date` is not frame-pure.
- **`@paper-design/shaders`** 0.0.82: eight shaders were checked and match Chrome. The others have not been run.

### GSAP

- A jump to a later frame (a still, or a worker starting at frame 600) renders the frames it skips without drawing them, so that tweens made in effects run. This costs one React render per skipped frame in a project that imports `gsap`.
- Motion-blur sub-frames run `onUpdate` but not `onStart`, `onComplete`, `onRepeat` or `call()`.
- `ScrollTrigger` and `Draggable` need scrolling and dragging, which a render does not have. `Flip` works.

See [GSAP](/docs/compat/#gsap) for what works.

### `@remotion/skia` and `@shopify/react-native-skia`

- Drawing is on the CPU only, so it looks the same on every machine. Offscreen surfaces too.
- SVG text uses your registered fonts. An unregistered family uses the fallback font and is reported. Missing characters are not drawn.
- Reanimated values live for one frame, so drive them from `useCurrentFrame()`. `withTiming`, `withSpring` and other clock animations jump to their end value and are reported.
- `useVideo` shows frames but no sound. Add an `<Audio>` of the file.
- Not supported: `makeImageFromView`, `Skia.SVG.MakeFromData` and touch handling.

More in [AUTHORING.md](https://github.com/0xS4N4TG/kinetograph/blob/main/packages/cli/skills/kinetograph/references/AUTHORING.md), section 7.7.

**Skia on the CPU when the GPU is Vulkan (Linux, Windows).** When Skia's Graphite cannot start on a Vulkan device, drawing falls back to the CPU backend. It is slower and anti-aliases slightly differently. The one-time warning, and `doctor --json` as `rendererReason`, name the GPU, driver and what is missing. Send that line if you hit it. `KINETOGRAPH_SKIA_CPU=1` chooses the CPU backend on purpose.

### `@remotion/rive`

- Set state machine inputs with the `stateMachineInputs` prop.
- Pictures and fonts are read from beside the `.riv` file, or from `assetLoader`. An asset on Rive's CDN is not fetched; it is reported.
- `getRenderer()` on the `ref` returns `null`.

More in [AUTHORING.md](https://github.com/0xS4N4TG/kinetograph/blob/main/packages/cli/skills/kinetograph/references/AUTHORING.md), section 7.6.

### HyperFrames projects

These notes cover [HyperFrames](https://github.com/heygen-com/hyperframes) projects. For what is supported, see [HyperFrames projects](/docs/compat/#hyperframes-projects).

- Three.js is not drawn. A page that loads it is reported on every frame.
- WebGPU shader blocks from `shaders.iife.js` (`aurora`, `blob`, `ripples`, `swirl`) are drawn. See [WebGPU](#webgpu).
- CSS and JSON import attributes are not supported.
- An import map with a `src` is ignored, as Chrome ignores it. Put the map's JSON inside the tag.
- A module graph must be in the cache. A specifier built at run time, such as `` import(`./locale/${lang}.js`) ``, is found by running the first frames in the pre-pass. One that shows only in an unsampled frame is downloaded on first use and noted. With `--offline`, it is an error that names the specifier.
- A picture URL a script builds is found the same way. If it is not found, or its host is not allowed, the picture is drawn without and reported. `doctor` gives the `fetch-deps` command to download it.
- `data-start` references stay inside one composition.
- In `data-color-grading` effects, the radii of blur, bloom and kuwahara count canvas pixels of the layer, so they scale with a transform. A missing or unreadable `.cube` file drops the `lut` and says so.
- A page that sizes text with `measureText` before its `@font-face` loads gets fallback widths in Chrome. Kinetograph measures with the registered font, so it can pick a larger size.

## Can look different

- **`preserve-3d` planes** are ordered and cut where they cross, using each element's border box. A shadow or glow past the box does not count. The crossing line is not anti-aliased. A layer cut more than 16 times (a card under a comb of 20 standing cards) is cut before it is warped, and can show a faint seam.
- **`backdrop-filter` on a turned element** mirrors the backdrop at the element's bounding box on the canvas, not at its turned or skewed edges.
- **A one-level difference in a few pixels** can appear when renderers share the GPU. Two renders at the same concurrency can differ by 1 in one colour channel on a frame. It is rare, and the cause is not found. For a bit-exact render, use `--concurrency 1` or `KINETOGRAPH_SKIA_CPU=1`. The CPU backend is slower on most scenes and its pixels differ slightly from the GPU's.
