Kinetograph is in beta, so APIs can still change between versions. The same list is in `CHANGELOG.md` at the root of the repo.

## Unreleased

### Added

- Plugins: a package whose `package.json` has a `kinetograph` field (`skill`, `panel`) is found from the project's dependencies. `kinetograph plugins [project]` and the `plugins` MCP tool list each one with the path of its `SKILL.md`, which agents read before using it. See `/docs/guides/plugins/`.
- `CompositionInfo.propsSchema`: the JSON Schema of the composition's zod 4 `schema`, omitted when there is no schema or it cannot be converted. The Studio Props tab draws fields from it: a select for an enum, a slider and number box for a number with `min` and `max`, a switch for a boolean, a colour input for `zColor()`, a text area for `zTextarea()`, a labelled group for an object, and the field's `description` as helper text. A field with `kinetographPanel` meta is drawn by that plugin's panel, with an error box if the panel fails.
- Studio presets: the Props tab has a Presets menu and a Save preset button. A preset is a file at `presets/<composition id>/<name>.json` beside the entry, served by `GET /api/presets` and `PUT /api/presets/<id>/<name>`.
- `--props` accepts the path of a JSON file as well as a JSON object, as Remotion's does.
- Plugin tools: set `"tools": "./tools.ts"` in the manifest and `kinetograph mcp` registers each tool as `<short>_<name>` (`hexed_roll`); `plugins --json` lists the names under `tools`.
- Studio live props: the window sends the props it previews, `GET /api/live-props` returns them, and `PUT /api/live-props` pushes new ones to every window. Both need the Studio token; the agent's MCP server gets a separate token that these two routes accept and every other route refuses.
- `kinetograph mcp --studio <url>` (token in `KINETOGRAPH_STUDIO_TOKEN`) adds the tools `studio_get_props` and `studio_set_props`. Studio passes this server to its coding agent in ACP `session/new`.
- Plugin metadata: set `title`, `description`, `icon` (an SVG in the package) and `components` (the exported React components that draw layers) in the `kinetograph` field. `GET /api/plugins` and `plugins --json` list them, and Studio serves the icon at `/api/plugins/<name>/icon.svg`. A plugin without a `title` shows under its package name, capitalised.
- Studio preview plays sound. The server mixes the composition's audio once, as a render does, and serves a WAV at `GET /api/audio?comp=<id>` and peaks at `GET /api/waveform?comp=<id>` (`buckets`, and `clip` for one clip). The Web Audio clock leads the picture, so the preview drops frames rather than drifting. Pause, seek and loop move the sound with the playhead, a scrub plays 80 ms snippets, and `M` mutes (kept per viewer).
- Studio timeline: audio clips draw their waveform and video clips a film strip of thumbnails, loaded only for the tiles in view.
- Studio range selection: drag the ruler or an empty lane to pick a span of time, click a clip for its span, Shift extends it, Escape clears it. The message to the agent then names the span and the Sequences and layers in it, and carries one contact sheet of up to eight frames instead of a single picture.
- Studio Props tab, plugin cards: a field owned by a plugin's panel is a card with the plugin's icon, title, version and description, a menu (copy the `SKILL.md` path, ask the agent about the plugin) and the panel. Clicking a card selects the layers its components draw, and selecting such a layer opens its card. A Plugins list at the bottom shows every installed plugin, used in this composition or not. A plugin's panel can draw an overlay on the preview.
- Studio export dialog renders the whole video or a custom range. Type the range as seconds, mm:ss or mm:ss.ff (the frame shows beside it), take it from the playhead with "Set to playhead", or set it on a trim bar of thumbnails. The dialog also has an output path (relative to the project folder) and a half-size draft switch.
- Studio command menu (Cmd+K or Ctrl+K) lists every action: export, reload, go to a composition, playback, zoom and safe zones, tools, panels, theme, switching or restarting the agent, and shortcuts. `?` opens a shortcuts dialog.
- Studio keeps the props you edited per project, a plugin panel's state (locks, open sections) per plugin and composition, and the panel sizes and theme, across a reload.
- A picture drawn many times in one `<Canvas>` or `<canvas>` is written once. The same `OffscreenCanvas`, canvas or `ImageData` drawn by many commands (a sheet as 250 clipped, transformed triangles) goes in the layer's new `sources` table, and each command holds a `{ "kind": "ref", "index" }`; the renderer decodes the pixels, or records the canvas's commands into a picture, once and replays it for every command under that command's clip and transform. Before, a drawn canvas's whole command list, and an `ImageData`'s base64 pixels (about 6 MB at 1150 x 1000, so 500 draws failed with `Invalid string length`), were copied into every draw. Measured on the M4 with `FoldOut` of the paper plugin: 203.6 ms a frame before, 41.4 ms after. One 1150 x 1000 canvas holding 5 pictures, drawn under 40 clips: the scene was 142 MB and the process peaked at 1.9 GB; with 500 draws it is 3.7 MB and 0.3 GB. One `ImageData` of that size drawn 40 times: 234 MB and 1.8 GB before, 5.9 MB and 0.37 GB now (500 draws failed before). The pixels are the same, byte for byte. A canvas with a clip, shadow or filter in it is still drawn command by command. An `ImageData` is hashed once for each frame it is drawn in (every draw when it is 128 x 128 or smaller), so a write to a large one between two draws in one frame is not seen by the second. See `SCENE.md` "canvas".
- `import tex from './tex.jpg'` (also `.png`, `.jpeg`, `.webp`, `.gif`, `.avif`, `.svg`) in a project or a plugin is the file's absolute path, which `<Img>`, `new Image().src`, `staticFile`-style code and a canvas's `drawImage` load. It used to fail the bundle with "No loader is configured".
- CSS filter functions on an element inside an `<svg>` (`blur()`, `drop-shadow()`, `brightness()`, `contrast()`, `grayscale()`, `hue-rotate()`, `invert()`, `opacity()`, `saturate()`, `sepia()`, mixed with `url(#id)` in order) are drawn. They were reported as unsupported and skipped. The `nyc-paris-flight` HyperFrames example now renders its route glow, route shadow and doodle shadow, and `doctor` flags no frame.
- Studio panels: a coding agent asks the person for a decision in a panel in the Studio window, with `studio_open_panel({ panel, data, message? })` (new in `kinetograph mcp --studio`; `panel` is `brief`, `script`, `storyboard`, `styleframes` or `review`). It returns `{ id, status: "open" }` at once and never waits. When the person submits or dismisses it, the server checks the answer, writes `plan/<panel>.json` beside the entry (inside the project, never through a link), and sends the agent the user message `[panel <kind> <id> submitted] <summary>; see plan/<kind>.json`, then the changes in short form, or `[panel <kind> <id> dismissed]`. A message that arrives while the agent is mid-turn waits for the end of the turn; with no agent running it waits for the next one. `studio_panel_result({ id })` returns `{ status, answer? }` for an agent that runs in a terminal. One panel per kind is open at a time (a new one dismisses the old), and a window that reloads gets them back. Routes: `POST /api/panels`, `GET /api/panels/<id>` (the agent's token or the window's), `GET /api/panels` and `GET /api/plan/<kind>` (the window's); WebSocket messages `panel`, `panel.closed`, `panel.error`, `panel.submit` and `panel.dismiss`. A panel opened for a script or a board is given the brief's `seconds` as `targetSeconds` when `plan/brief.json` exists.
- Studio stage stepper: once a panel has been opened, a strip over the preview shows Brief, Script, Board, Style, Animatic, Build and Deliver as empty, open (click to bring the panel up) or approved. A panel is a sheet over the preview; a review is docked in a column beside it so the preview stays in view. Deliver opens the export dialog.
- `makeWebFont(cssUrl)` in `@kinetographdev/core/fonts` loads the fonts of any `@font-face` stylesheet URL, as `makeGoogleFont` does for Google: `makeWebFont(url).loadFont('italic', { weights: ['700'] })`. The stylesheet is read for the current file links (Fontshare's `https://api.fontshare.com/v2/css?f[]=switzer@400,700`), each face is registered with its own weight, style and the stylesheet's `font-family`, TrueType or OpenType files are preferred, and `//cdn...` links resolve against the stylesheet URL. A file that answers 404 makes the stylesheet download again past the cache and the file is taken from its new answer. A plugin no longer needs to pin file links that change with each release. See `AUTHORING.md` §7.2.

### Changed

- Studio layout: the menu bar is gone. A top bar (project, composition switcher, command menu, theme, export) sits over floating panels: agent chat on the left, preview in the middle with the timeline under it, inspector (Props, Scene, Renders) on the right. Drag a side panel's or the timeline's edge to resize it (double click resets), and fold the agent and inspector from the top bar. The preview is larger, with a floating transport (play, step, a timecode box that takes a frame or mm:ss.ff, progress, preview fps, mute, loop) and a floating tools and View menu (layer controls, safe zones, zoom). Props is the first inspector tab. Cmd+K replaces the menu bar, and switching or restarting the agent moved into it.
- Studio timeline is a slim bar that expands to layer rows, drawing only the rows in view. Clips are coloured by kind (Sequence, text, shape, group, image, video) with the kind's word before the name, the ruler counts in mm:ss.ff with marks at their true time positions, and a timecode box shows the playhead.
- Studio renders the agent's replies as markdown (Streamdown). Remote images are not loaded, links must be http or https, and the page's Content-Security-Policy allows images only from the page itself, `data:` and `blob:`.
- A DOM island is no longer rebuilt from nothing on every frame just because a stylesheet mentions `transition`, `animation` or `@starting-style` (every Tailwind build does, with `.transition` and `@keyframes spin`). An imported sheet counts only when a rule that sets a transition or an animation has a selector that can match an element of the island, and only then is the island's history sent and replayed. A sheet that names `border-collapse` (Tailwind's preflight) no longer keeps an island out of the cache when it collapsed no table.
- An island's fonts are matched against decoded font files kept across frames, and its pictures' sizes are kept, both keyed by path, length and modification time, so a font or picture file is no longer read again on each frame.

### Fixed

- The error for an entry that never calls `registerRoot` says to import it from `@kinetographdev/core` and that a file exporting only a component is not an entry. Importing the video API from `kinetograph` (the CLI) adds a hint naming `@kinetographdev/core`.
- On Windows, `staticFile()` paths such as `D:\proj\public\x.png` load. `<Img>` and the resource loader read the drive letter as a URL scheme and skipped the file (#27); they now treat a drive path as a path before parsing it as a URL. A root-relative `/x.png` (`D:\x.png` on Windows) was looked up in the public directory as a rooted path and missed, so every frame warned (#28); only the path's names are kept now (#71).
- A variable font declared with a weight range (`@font-face { font-weight: 300 1000 }`, or `new FontFace(..., { weight: '300 1000' })`) was registered at its first weight and held there. It now follows the weight a text asks for within the range: `font-weight` and `font-variation-settings` in the DOM, and `ctx.font = '1000 40px Name'` on Canvas 2D, whose `measureText` and `fillText` ignored the weight before (they shaped at one instance and drew the font's default). A HyperFrames page that checks its variable font's axis by drawing at two weights, as `weight-wave` does, now passes.

## 0.2.5 (2026-10-28)

### Added

- HyperFrames audio effects: `data-fx-chain` is now played on an `<audio>` or audible `<video>`, on an `<hf-audio-group>` and on the root composition (the master bus), with all sixteen effects, the presets' blends and the `fx.*` and `fx.preset.*` lanes of `data-automation`. Order follows HyperFrames' mixer: `data-volume` ahead of the chain, the volume lane and fades after it, effect tails up to 5 s, group buses, the master chain over the mix. HyperFrames' effect graph and AudioWorklet processors (Apache-2.0) are ported to `@kinetographdev/audio` and run on node-web-audio-api, with no browser. Against HyperFrames' effects runtime in Chrome, 38 cases match in level to 0.000 dB, and a mixed page rendered by both CLIs is within 0.01 dB. Before, the chain was ignored. See `/docs/compat/#hyperframes-projects`.
- HyperFrames pages: `html` and `body` are the document's own elements. Their rules for `html`, `body` and `:root` apply with their own specificity, `rem` follows the `html` font size, and scripts see `document.documentElement` and `document.body` (`getComputedStyle(document.body)`, `document.documentElement.style`, `document.body.appendChild`, `querySelector("body")`, `:root`). Before, they were two wrapper elements and the page's selectors were rewritten to match. A test page that styles both went from 16.3 to 0.06 mean levels off HyperFrames' still.
- Intel and AMD GPU encoders on Linux: `--encoder h264_vaapi`, `hevc_vaapi`, `h264_qsv` and `hevc_qsv` run in a system ffmpeg (`KINETOGRAPH_FFMPEG=$(which ffmpeg)`). They get the device and upload filter they need, `--crf` mapped to VAAPI's `-qp` and Quick Sync's `-global_quality`, `yuv420p` (`yuv420p10le` for HEVC), and a test encode before they are accepted, as for NVENC. `KINETOGRAPH_VAAPI_DEVICE` picks the render node. Never the default. Checked by unit tests and a stand-in ffmpeg, not on real hardware yet.
- `kinetograph doctor` (and `--json`, as `rendererReason`) and the one-time CPU-fallback warning say why Skia's Graphite could not use a Vulkan GPU: the device and driver, and the Vulkan version, function or image-format usage that is missing. The addon method is `Renderer.backendReason()`.
- `kinetograph track <video> --point x,y [--point ...]` follows points through a video with libmv, as Blender 4.5's "Track Markers" does (its six motion models, pattern and search sizes, keyframe or previous-frame matching, backwards tracking, the margin check and where a track is lost), and writes `<video>.track.json`. `useTrack(file, trackName?)` in `@kinetographdev/core` returns `{ x, y, scale, rotation, corners }` for the current frame. Tracking runs before a render, never during one. Against Blender on the same clips, the same frames are tracked and lost and markers agree to within 0.0002 px. The addon now includes libmv (MIT), Ceres Solver (BSD-3-Clause, with Apache-2.0 parts from Abseil), miniglog (BSD-3-Clause) and Eigen (MPL-2.0); their licences are in the platform packages.
- `kinetograph track --detect` and `--plane`, as Blender's Detect Features and Create Plane Track. `--detect` places points with libmv's Harris detector (defaults: threshold 0.5, minimum distance 120 px, margin 16 px; `--detect-inside`/`--detect-outside` polygons for annotation placement) and tracks them. `--plane p1,p2,p3,p4` (or `all`) makes a plane track from four or more point tracks, with corners from the patterns' bounding box or `--plane-corners`, carried through the clip by libmv's homography. The track file gains `planes`. `usePlaneTrack(file, planeName?)` in `@kinetographdev/core` gives `{ corners, pin }` for the current frame, and `cornerPin(pin)` pins a layer to the plane. Against Blender on the same clips, detected features are the same and in the same order, and plane corners are bit-equal on every frame. The motion-tracking guide shows how to steady a shot with `useTrack`.
- `onVideoFrame` on `<Video>`, `<OffthreadVideo>` and `<Html5Video>`, as Remotion has had it since 4.0.190. Your code gets the frame the video shows at each composition frame, as a canvas image source decoded by the engine's own decoder (a pure function of the frame number, whichever frames were rendered before). `ctx.drawImage(frame, ...)` (all three forms), `createPattern`, WebGL's `texImage2D` and WebGPU's `copyExternalImageToTexture` accept it, and `getImageData` of the canvas returns its pixels, alpha included.
- Canvas 2D `drawImage` of a `<video>` element draws the frame at its `currentTime` (HyperFrames pages set it from the timeline). A `canvas` layer takes the source `{ "kind": "video" }` (SCENE.md, "canvas").
- `getImageData` and `texImage2D` of a canvas that holds one plain `drawImage` of a picture file or a video frame are answered on the CPU from the decoder's cache (addon `readCanvasPicture`), with no GPU: 0.7 ms against 3.3 ms for a held 1080p frame, 39 ms against 101 ms for the first call. Any other canvas is drawn by the renderer as before.
- Web Animations API on the frame clock: `element.animate()`, `KeyframeEffect`, `Animation` (`currentTime`, `startTime`, `playbackRate`, `play`, `pause`, `finish`, `cancel`, `reverse`, `updatePlaybackRate`, `commitStyles`, `ready`, `finished`, `onfinish`, `oncancel`), `getAnimations()` and `document.timeline`, with `cubic-bezier()`, `steps()` and `linear()` easing and the `add` and `accumulate` composite modes. Values mix as Chrome mixes them (legacy colours in sRGB with premultiplied alpha, others in Oklab; transform lists by function or by matrix), and 27 cases match Chrome for Testing 154. Motion now runs `opacity`, transforms, `filter`, `clipPath` and colours on it instead of its JavaScript fallback, and its values match Chrome's to 0.0005, springs and `oklch()` colours included. A frame alone still equals the frame in sequence and at any concurrency.
- `render`, `still` and `doctor` warn, once per render, when a GSAP tween plays on GSAP's root clock instead of a paused timeline seeked to the frame. Kinetograph renders it the same alone and in sequence, but Remotion's and HyperFrames' own renderers do not.
- 3D glTF occlusion and emissive textures are drawn as glTF 2.0 specifies: occlusion at its `strength` darkens the ambient light and the environment (not directional lights), and the emissive texture multiplies the emissive factor. Before, they were reported and left out.
- 3D `bevel` on `text` and `extrude` objects (`<Text3D bevel>`, `<Extrude bevel>`): `{ thickness, size, offset, segments }`, as three.js's `ExtrudeGeometry` bevel options.
- 3D morph targets and skins are deformed on the GPU, in a compute pass each frame, instead of on the CPU. A 204,800-vertex skinned, morphing model draws a 1080p frame in 3 to 5 ms on the M4 against 10 to 12 ms (four of them: 9 to 15 ms against about 30). A part with more data than one storage buffer holds (a big morph rig) is still deformed on the CPU. A vertex whose skin weights are all 0 follows its first joint, as in three.js, instead of collapsing to the origin.
- 3D shadows: every light may cast them. The maps are layers of one depth texture array (up to 48, a point light taking 6) within 1 GiB, and the old limits of 4 shadow lights and 8 maps are gone.
- WebGPU `rgba16float` canvases are drawn at half-float precision into the compositor, and a `display-p3` `colorSpace` is converted to sRGB primaries. Before, both were reported and drawn as 8-bit sRGB. Output stays SDR, so values outside 0 to 1 are clipped; `toneMapping: 'extended'` is drawn as standard and reported.
- WebGPU frame texture budget is 4 GiB (three of the biggest textures the device's limits allow), up from 512 MiB, which refused a single `rgba32float` 8192 x 8192 texture with its levels. Chrome on the M4 made 4 GiB of textures without an error.
- WebGL framebuffers do what Three.js's renderer needs, drawn natively and checked against Chrome for Testing: the stencil test (`stencilFunc`, `stencilOp`, `stencilMask` and their `Separate` forms, `clearStencil`, the canvas's `stencil` attribute, stencil renderbuffers); several colour outputs (`COLOR_ATTACHMENT1` to 7, `drawBuffers`, `clearBuffer*`, `layout(location = n)` outputs); depth and depth-and-stencil textures as attachments, sampled as Chrome samples them; colour, depth and stencil renderbuffers, with one depth buffer shared by the framebuffers that attach it; a texture level above 0 as a target, with `TEXTURE_MAX_LEVEL`; `blitFramebuffer` of depth and stencil; and `texSubImage2D` from an image or a layer, into a texture drawn in or one made from a file.
- Canvas 2D `ctx.filter = 'url(#id)'` draws the SVG `<filter>` of the page it names, in its place in the filter list, as Chrome does.
- `studio` downloads what an edit newly needs without a restart. When any project file changes (the page, the compositions it mounts, the local modules it imports), the step before frame 0 runs again after a short wait for a save that touches several files, and fetches only what is not cached. A dependency added in a sub-composition or local module is there on the next rebuild.
- HyperFrames modules: `import()` of a specifier built at run time (`` import(`./locale/${lang}.js`) ``, a bare name held in a variable) works. The pre-download pass runs the page's first frames (frame 0, the last and up to six between) with a hook on `import()`, resolves each requested specifier through the import map, downloads and locks it, and the render bundles it from the cache. A specifier first seen mid-render is fetched once, locked and noted; with `--offline` it is an error that names the specifier.
- HyperFrames modules: a module whose download was redirected resolves its relative imports and `import.meta.url` against the final response URL, as a browser does. The cache keeps the final URL beside the file and the lock records it as `final`. A redirect to a host that is not allowed is still refused.
- A plain HTML page whose root element lacks `data-composition-id`, `data-width`, `data-height` or `data-duration` gets a warning from `doctor`, `render` and `still` that names what is missing and shows the one-line fix. `--strict` fails on it, as on other unsupported content.
- `doctor`, `render` and `still` report the errors a page's own scripts raise and survive: `console.error` calls, uncaught exceptions and unhandled promise rejections, once per message per frame, with the frames they were seen on. A library that catches its own failure (Mermaid) no longer passes as clean. `--strict` fails on them.
- Constructable `CSSStyleSheet` (`insertRule`, `replaceSync`, `cssRules`, `rule.style`), for scripts that build CSS text.
- DOM for sanitizers: `DOMParser` (`text/html` and the XML types, including `image/svg+xml`), `document.implementation.createHTMLDocument` and `createDocument`, `document.createNodeIterator` and `createTreeWalker` (the iterator moves on when the node it stands on is removed, as sanitizers rely on), `NodeFilter`, `DocumentFragment` (also `document.createDocumentFragment`), `<template>` with `.content`, `Element.attributes` (`NamedNodeMap`, `Attr`, `getAttributeNode`, `removeAttributeNode`), `Node` with `nodeType`, `nodeName` and `ownerDocument` on text nodes too, `HTMLTemplateElement` and `HTMLFormElement`. DOMPurify finds its document through them. Mermaid 12 renders flowcharts, sequence diagrams, class diagrams and pie charts when its labels are SVG text (`mermaid.initialize({ htmlLabels: false })`); see `/docs/known-issues/` for HTML labels.
- WebGL depth test is drawn: `enable(gl.DEPTH_TEST)`, `depthFunc`, `depthMask`, `depthRange`, `clearDepth`, `clear(DEPTH_BUFFER_BIT)` and `polygonOffset`, on the canvas (the `depth` context attribute) and on a framebuffer with a depth renderbuffer (`renderbufferStorage`, `framebufferRenderbuffer`). The HyperFrames composition `code-slice-hero` now renders all 240 frames in `doctor`. A colour or stencil renderbuffer, a depth texture and the stencil test were still reported at this point. See `/docs/known-issues/#webgl`.
- The GPU device allows up to 16 vertex buffers (was 8), so a `glsl` draw with more than 8 attributes draws. WebGPU pages still see `maxVertexBuffers` 8 on every machine.
- Script writes to an element's classes and data attributes reach the page: `svgElement.className.baseVal = 'on'`, `classList.replace()`, `classList.value` and `element.dataset.key = 'x'` (and `delete element.dataset.key`) were lost, so selectors that read them never matched. Tests now also cover a class added, removed or toggled on an SVG shape between frames, `setAttribute`, the `style` attribute, a sibling's class, `:nth-child` after a node is inserted, and a rule inside `@media`; a class or attribute added to an SVG shape between frames already restyled it.
- HyperFrames `effects` in `data-color-grading` are drawn: blur, bloom, kuwahara, chromaBleed, pixelate, halftone, twoInkPrint, ascii, dither, monoScreen, scanlines, chromaticAberration, crtCurvature, digitalGlitch, tapeDamage, filmArtifacts, engraving and crosshatch, with all 64 controls, the `palette`, the presets' own effect values and the tweened `--hf-color-grading-blur|bloom|kuwahara|pixelate|ascii|dither`. They are no longer reported as not drawn. See `/docs/compat/#hyperframes-projects`.
- `colorGrade` is a scene effect of its own, with the helper `colorGrade({ effects: { halftone: 0.9 } })` in `@kinetographdev/scene`, so your components can use the grade and the look effects. The catalog lists 23 effects now.

### Changed

- Blur radius limit: `blur`, `backdropBlur`, `glow` and a shadow's `blur` clamp at 16384, up from 512 (blur) and 128 (the others). Each image of a blur's pyramid holds only what the blur draws in it, so a 1000 px blur needs about the memory of a 128 px one (22 MB on 1080p, down from 579 MB). No blur texture is larger than the device allows (8192 px a side): a mirrored backdrop blur whose canvas (the box plus three radii each way) would be larger is drawn shrunk and enlarged after. The canvas margin still makes room for a radius of at most 128.
- Scene `backdropBlur` has `edgeMode`: `canvas` (default) or `mirror`, which reads only the layer's box, mirrored.
- Scene gradient paint has `tile` (paint it in one tile and repeat it, with gaps), and image paint has `spaceX` and `spaceY`.

### Fixed

- Motion-blur sub-frames sample GSAP tweens that play by themselves at the sub-frame's time, with their `onUpdate`. Before, every sub-frame showed the frame's own state, so those tweens were not blurred. A blurred render's frames equal an unblurred render's, and a frame alone equals the frame in sequence.
- SVG `getBoundingClientRect` matches Chrome for Testing: the `<svg>`'s `preserveAspectRatio` (`none`, `slice`, the alignments), a CSS `transform` with its `transform-origin`, and nested `<svg>` viewports are now included. Strokes, markers and filters stay out, as in Chrome.
- A canvas pattern of another canvas covers any number of tiles (it stopped at 10,000), and a pattern of a canvas pass's child is drawn (it was left out).
- Canvas `ctx.filter = 'drop-shadow(...)'` uses its blur length as the standard deviation, as Chrome does; it was halved.
- Canvas `isPointInStroke` takes the line width, caps, joins, miter limit and dashes into account, in the current transform, as Chrome does.
- WebGL: explicit `layout(location = n)` on a shader's inputs and outputs is honoured; the translator dropped it.
- WebGL: with the default `antialias`, `blitFramebuffer` into a canvas, or out of it into a rectangle of another size, sets `INVALID_OPERATION`, as Chrome's multisampled canvas does.
- GPU-compositor layers (a `preserve-3d` context, an effect only the compositor draws) that blur their backdrop see what Skia drew before them, as `backdrop-filter` sees everything painted before the element. A frosted panel in a `preserve-3d` group over a box outside the group was not frosted at all. In a scene that blends in sRGB (every DOM and Remotion scene) the compositor now blurs a backdrop on sRGB-encoded values, as Skia and Chrome do; it blurred in linear light, which made a frost over a colour edge lighter. Against Chrome for Testing the repro went from 1.63 to 0.02 mean levels (max 98 to 1), and a frosted panel with the box inside the group from 0.83 to 0.02. A frame without a backdrop blur draws as before; one with such a layer costs about 0.8 ms more on the GPU at 1080p.
- `transform-style: preserve-3d` planes that cross each other intersect, as in Chrome. The layers of a 3D context are ordered by a BSP tree of their planes, and a plane another crosses is cut where they meet, each piece in its own place in the order (two cards pushed through each other, a card flip, a cube; 0.65 mean levels from Chrome for Testing). Parallel planes are ordered by their planes rather than their centres, so a tilted stack of cards no longer puts a farther card in front.
- A `display: inline-block` element that is also a stacking context (a `transform`, `opacity`, `position: relative`, ...) is drawn once. It came out as two identical layers (`$0.0.1` and `$0.0.1~2`), which doubled its anti-aliased edges and translucent fills.
- `background-repeat: space` and `round` work with any number of tiles. Past 150 tiles of a gradient or a picture, the tile is drawn once and the paint repeats it at its exact period, gaps included, as Chrome's pattern shader does. Before, `space` with thousands of gradient tiles warned and drew nothing, and `round` drifted by up to a tile.

- `@remotion/rive`: `stateMachineInputs` sets a state machine's inputs (an object, or a function of the frame; each change is met at its frame's time as the machine is replayed, so a frame stays a pure function of the props). Referenced pictures and fonts are read from beside the `.riv` or given by `assetLoader` (a CDN asset is reported). `onLoad` gets the file's artboards, animations and state machines, `effects` and `effectsOutputSize` run over the canvas, and the `ref`'s `getCanvas`, `getArtboard` and `getAnimationInstance` answer (`getRenderer` stays `null`).
- Studio chat survives a reload: the server keeps the conversation and replays it to the window that comes back within 30 s, and the agent keeps running meanwhile.
- Studio timeline clips show a thumbnail of their first frame. Thumbnails are drawn one at a time, only while no preview frame is being asked for, and kept. On `examples/compat`, playback took 10.2 to 10.8 ms a frame with 40 thumbnails waiting and 10.8 to 11.4 ms without; each thumbnail took about 5 ms in the idle time after.
- Studio numbers siblings that share a name ("Card", "Card 2", "Card 3") in the timeline, the scene tree, the preview and the chat's context.

No prebuilt Skia for skia-safe 0.153.3 has the GPU backend (Graphite on Metal) together with the text-layout and SVG modules this addon uses, so the GPU path would mean building Skia from source on every platform, and GPU pixels differ from the CPU's and between machines. A busy 1920 x 1080 canvas (gradient, 40 circles, a blurred rounded rect, text, a blurred circle) costs 9.9 ms a frame to draw, read back and hash, plus 8.0 ms to encode and write its PNG (0.39 MB) when the picture is new.
- Studio's agent no longer reports a turn as done after the conversation was stopped.
- `img.src = url` set from a script draws. `src` had a getter and no setter, so nothing drew and `doctor` called the page clean. Now `src`, `srcset`, `sizes`, `alt`, `poster`, `href` and `currentSrc` reflect their attribute as in a browser. An SVG element's `href` is an SVGAnimatedString (`image.href.baseVal = url`). `src`, `href`, `poster` and `currentSrc` read back resolved against the document's URL, so `new URL(link.href)` parses. An `<img srcset sizes>` is parsed as HTML parses it and drawn with the candidate Chrome takes at device pixel ratio 1. In a HyperFrames page, a remote picture set at run time is read from the pre-download cache: `fetch-deps` finds its URL in the page's scripts, or runs the page's first frames when a script builds it, and a render that misses it reports it with the `fetch-deps` command.

- A scene-file key the format does not read (`bogusTop`, a misspelt `opacty`, `radius` on a `rect`) is warned about by `render`, `still`, `lint` and `doctor` with its JSON path, on every frame, and `--strict` fails on it. Before, it was ignored without a word.

- HyperFrames colour grading: `crtCurvature` on an element bigger than the canvas pulls in the part off the canvas, as Chrome does; it drew black there (a 1600 x 900 image on a 1280 x 720 page: 27.2 to 0.31 mean levels off HyperFrames' still). The HTML in a `<foreignObject>` is laid out as a block box of the object's `width` and `height` (the attributes, or CSS), painted by the HTML painter (text, backgrounds, borders, flex, nested SVG), cut to the box by its `overflow`, and carried through the SVG's `viewBox`, transforms, opacity and clip. `doctor` reports per frame what cannot be drawn (a percentage size, HTML in a clip path), and the shapes beside it are drawn. Before, they filled the line or held nothing. Libraries centre labels with them.

- A React-path `<canvas>` that a frame draws on starts that frame empty, as the docs say. A canvas nobody draws on in a frame keeps its pixels, so one drawn once in `useEffect(..., [])` still shows. Before, it kept the previous frame's pixels, so `still 45` (or a render worker that starts mid-way) drew a different picture from frame 45 of a full render. A plain HTML page still keeps its canvas between frames.
- Mermaid's `calculateTextDimensions` no longer throws `svg element not in render tree`. SVG text is measured with the built-in fallback font when its family is not registered, and `getBoundingClientRect` of an SVG shape in an `<svg>` with no layout box answers in the SVG's own units.
- `outerHTML` and `innerHTML` write SVG attributes such as `viewBox` and `markerUnits` in their proper case below the `<svg>` element; they wrote lower case. A `style` given as text was written as nothing, and an element inside `<foreignObject>` reported the SVG namespace (and `<br>` parsed as an unclosed element).
- Nodes made by `innerHTML` or `insertAdjacentHTML` below the first level have a `parentNode`; it was null.
- `document.querySelector('body')`, `querySelectorAll('html')` and `getElementsByTagName('body')` find `html`, `head` and `body`; they returned nothing, which broke `d3.select('body')`.
- `lut` effect: `interpolation: 'trilinear' | 'tetrahedral'` (default `'trilinear'`). Tetrahedral blends four table points chosen from the six-tetrahedra split of the cell, as DaVinci Resolve, OpenColorIO and ffmpeg's `lut3d=interp=tetrahedral` do.
- `render`, `still`, `doctor`, `studio` and the other commands that open a project download what it loads from the web before frame 0, then draw offline. HyperFrames pages: CDN scripts, data, media, pictures and fonts, as `fetch-deps` did. Remotion projects: the https pictures, videos and audio that `<Img>`, `<Video>` and CSS `url()` name in the bundle. `--offline` never downloads. `fetch-deps` stays as the explicit command, works on Remotion entries, and gains `--update`.
- `kinetograph.lock.json` beside the entry pins every downloaded file (URL to SHA-256 and size), written on first download. Later runs check the cache against it and stop with the URL on a mismatch; `fetch-deps --update` accepts new bytes. A Remotion URL first requested in the middle of a render is downloaded once, added to the lock and noted. Cache writes are atomic (hash first, file last), so parallel workers on a first render never read half a file.
- HyperFrames: `<script type="importmap">` (`imports`, `scopes`, trailing-slash prefixes) and `<script type="module">` that import now work. The graph (bare names through the map, URLs, relative paths, `export * from`, esm.sh `/v135/...` paths, dynamic `import("...")`) is downloaded in the pre-pass and locked, and each module script is bundled by esbuild from the cache into a classic script that runs after the classic scripts, in document order. `import.meta.url` is the module's URL. `cdn.skypack.dev` joins the default hosts.
- CSS Motion Path moves and turns the element: `offset-path` (`path()`, `circle()`, `ellipse()`, `inset()`, `polygon()` and `ray()`), `offset-distance` (lengths and percentages of the path; a closed path wraps, an open one stops at its end), `offset-rotate` (`auto`, `reverse`, angles), `offset-anchor` and `offset-position`. GSAP tweens of `offsetDistance` animate. The offset transform sits between `translate`/`rotate`/`scale` and `transform`. Not followed, and reported: `url()` paths, `shape()` and a lone `<coord-box>`. Rounded `inset()` corners and `ray(... contain)` are approximated.
- `white-space: nowrap` keeps inline-blocks on one line when no text comes before them; a row of `inline-block` tiles in an absolutely positioned box without a width used to wrap. Parley took the wrap mode from the last text only; it is now vendored (`vendor/parley`) and starts from the container's.
